# Managed dependencies and local foreground separation

The repo owns the integration and setup code. Third-party engines are installed into its isolated runtime; they are not rewritten or relicensed as this project's code. Python 3.11+, Codex/image-generation access and Grok account access remain external prerequisites.

## Media runtime

`install.py` verifies Python requirements and calls `media_runtime.py --install`. Existing system tools are reused. Missing FFmpeg/ffprobe are fetched through pinned `static-ffmpeg==3.0` into the installed Python package's cache under `.venv`. Its platform support currently includes macOS Intel/ARM, Linux x86-64/ARM64 and Windows x86-64; unsupported platforms need explicit executables. Actual platform/codec support is checked at use, not inferred from a filename.

```sh
.venv/bin/python scripts/media_runtime.py --install
.venv/bin/python scripts/media_runtime.py --install --managed
.venv/bin/python scripts/doctor.py
```

Rendering resolves explicit `VIDEO_GIF_FFMPEG` / `VIDEO_GIF_FFPROBE` executable paths, then PATH, then managed binaries. These are file paths, not shell commands. Invalid overrides fail instead of falling back. Doctor/rendering do not download; installation does. Video exports and music analysis/muxing all use this resolver. Managed binary setup verifies both executables can run; export tests still validate required codecs and alpha output. Initial installation needs network access. The upstream downloader owns its download catalog/integrity behavior; this repo does not claim an independently pinned binary checksum.

## Optional local masking

```sh
python3 scripts/install.py --with-matting
.venv/bin/python scripts/background_remove.py prepared/frames \
  --manifest prepared/manifest.json --out output/masked --model u2netp
.venv/bin/python scripts/video_export.py output/masked/frames \
  --manifest output/masked/manifest.json --out output/masked.webm
```

The optional `rembg[cpu]` backend uses ONNX Runtime. Model choices are `u2netp` (small default) and `u2net`. Weights download on first use to `.runtime/models`, or an explicit `U2NET_HOME`; do not commit them. Input must be prepared numeric PNG frames with a timing manifest. Source RGB, shared canvas and timing are preserved; predicted masks multiply existing alpha, preserving interior holes and partial alpha. Source files remain untouched. Model inference happens locally after downloading weights.

This is **framewise foreground segmentation**, not a temporal model, semantic character/effect layer separation or guaranteed production matting. Review every resulting edge and temporal flicker over light and dark backgrounds. Keep the existing uniform-color keyer for suitable sources. Do not use this as an automatic pixel-art redraw/smoothing step; keep the pixel-native workflow. No new media is generated by installation.

## Authentication and external services

Grok REST submission/polling/download is internal. Default OAuth still uses the official Grok CLI for browser sign-in and refresh. Explicit `--auth api-key` directly reads `XAI_API_KEY` and needs no Grok CLI. There is no automatic billing-mode fallback. Model access, quota, account authorization and Codex's image-generation service cannot be supplied by copying code into the repo.

## Upstream software

- [static-ffmpeg](https://github.com/zackees/static_ffmpeg): managed binary downloader. Downloaded FFmpeg builds retain their own licenses and source obligations; the repo's MIT license does not relicense them.
- [rembg](https://github.com/danielgatis/rembg): optional foreground-segmentation integration and model download handling. Backend/model licenses remain upstream.
- [Grok authentication documentation](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/02-authentication.md): official OAuth and API-key account routes.

No MV Studio, `motiongen.py`, lyrica-studio checkout or developer-specific workspace path is required.
