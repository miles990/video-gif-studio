# NEON ZEN — 流光入靜

[English](README.md) | **繁體中文**

30 秒音樂 PV 實驗：原創銀白機械錦鯉從霓虹雨巷游入水庭，掠過水面、帶起漣漪，最後收束。以五次 Grok 生成串接，每段使用上一段的實際尾幀與固定角色參考圖；搭配使用者提供的 **Neon Zen**，音樂保持原速。

## 畫面與卡點

| 成片時間 | 實際畫面 |
| --- | --- |
| 0–5.55 秒 | 擺尾滑行，轉入庭院。 |
| 5.55–11.73 秒 | 迴游靠近鏡頭，展現魚身。 |
| 11.73–17.60 秒 | 沿水庭側向掠行。 |
| 17.60–24.20 秒 | 魚鰭降低，水面漣漪散開。 |
| 24.20–30 秒 | 鏡頭展開成遠景，動作收束。 |

使用原曲 **19.96–49.96 秒**。分析得到約 **82 BPM** 的候選，存在半拍／倍拍歧義，因此交接時間選自實際能量突起，不宣稱是經聆聽確認的強拍。30 秒終點是指定片長。

另外測試兩個段內卡點：第一段第 84 幀的轉身畫面放在 **3.50 秒**；第四段第 80 幀、漣漪清楚散開的畫面放在 **21.27 秒**。以原始影格分段調整曝光時長，沒有光流補幀、混合疊影或逐幀重畫，音樂也沒有變速。

## 來源與重製

沒有使用者提供的參考圖。起始圖由 Codex 可用的圖片工具生成，工具未回報可核實的模型版本；題詞見 [image-prompt.txt](image-prompt.txt)。五段影片均由 `grok-imagine-video-1.5` 生成，原始規格為 1280×720、24 fps，每段 145 幀；光跡、水滴與漣漪都由 Grok 產生。

這次透過 `/videos/generations` 的首圖加多張參考圖功能續接，並非影片延長端點。範例附有使用 repo 內部 client／ledger 的小型 adapter，仍由 Codex 逐段檢查與串接，不表示通用自動 chain runner 已實作。已公開的輔助程式調整成相對路徑；紀錄中的 adapter 雜湊對應原本本機程式。

最終 MP4 為 960×540、有聲、不透明背景。100 fps 是表達 10 毫秒影格時長的編碼時基，重複影格不等於每秒生成 100 個新動作。GIF 僅為無聲片段預覽，未設計成無縫循環。

使用者授權這首音樂作為範例。檔案中繼資料標示 **wizardx07 / Neon Zen / made with Suno**，僅附選用的 30 秒 `soundtrack.flac`，詳見 [音樂來源](music-provenance.json)。MIT 程式授權不額外授予音樂使用權。

在 repo 根目錄完成安裝後，可依序執行：

```sh
for n in 1 2 3 4 5; do
  .venv/bin/python examples/neon-zen-pv/prepare_segment.py "$n"
done
.venv/bin/python scripts/compose_timeline.py examples/neon-zen-pv/timeline.json \
  --out output/neon-zen-rebuild --formats mp4
```

PNG 工作影格不放入 Git，可從附帶來源影片重建。輸出使用新目錄；改時間表與重新剪輯不需要 Grok。重新生成影片會消耗額度，不能保證同樣像素。

## 驗證範圍

已檢查來源聯絡表、四個接縫前後畫面，並保留 [輸出驗證](delivery-qc.json)、[時間表紀錄](delivery-manifest.json)、[接縫數據](chain-qc.json)、[動作卡點驗證](event-qc.json)。每次提交的首圖都與前一段解碼尾幀完全相同；下一段實際首幀經編碼後有約 3.0–3.8/255 的平均 RGB 差異。

**完整播放與聆聽美感審閱尚未認證**。能量突起不等於樂理強拍；首尾圖一致也不代表速度銜接一定自然。部分中段魚尾留邊偏緊，細小鱗片／魚鰭細節仍有生成變動。這是可用於驗證串接與卡點的工作範例，不宣稱角色或節奏毫無瑕疵。
