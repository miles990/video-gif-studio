# 路線修訂 — spec-5（2026-11-04，依 research/synthesis.md）

本檔**重新排序** spec-2～4，並補上調查發現的缺口。spec-2～4 的條目仍有效，但依下列優先序建造；衝突時以本檔為準。
流程照 process.md：trunk-based、每個切片過測試＋審查（效果另過品質閘門）即合回 main 並 push。

## P0 交付層（不修就交不出片；最先做）
- S-50 **串流算繪**：影格邊算邊送進 ffmpeg 編碼（pipe），記憶體與片長無關；量測：1080×1920、30 秒、3 個效果的峰值記憶體 ≤ 1.5 GB。
- S-51 **固定影格率輸出**：MP4／MOV／WebM 預設 30 fps（可選 24/25/50/60），拍點事件量化到該影格網格並寫明誤差（≤ 半格）；
  GIF／APNG 維持自己的 10 ms 時基。舊 100 fps 行為只在明確要求時保留。
- S-52 **平台預設**：`--platform tiktok|reels|shorts|youtube|square`：尺寸、fps、位元率、色彩（BT.709）、安全區（字幕避開 UI）。
- S-53 **聲音**：保留原片聲音（可選）、配樂在人聲下自動降低（ducking）、整體響度正規化到 −14 LUFS、true peak ≤ −1 dBTP（ffmpeg loudnorm 兩段），
  qa_media 不過就擋交付。
- S-54 **手機素材進件**：VFR→CFR、旋轉 metadata、HDR→SDR（tonemap）、保留音軌與音畫同步檢查；附 iPhone／Android 樣式的合成測試片。
- S-55 **效能**：熱點 cv2 化與緩衝重用（第二輪進行中），並提供 `--proxy`（spec-3 S-33 提前）；記錄 720p／1080p fps 與峰值記憶體。

## P1 最大感知差（競品證實最能拉開業餘與專業的差距）
- S-56 **逐字動畫字幕**：faster-whisper（MIT，選用依賴）逐字時間戳；也接受使用者給的 SRT／文字稿。字幕樣式系統（欄位：字型、大小、描邊、陰影、
  底框、關鍵字顏色、進場動畫 pop／typewriter／bounce、每行字數、位置、安全區）；中文斷行（不拆詞、標點不起行）；關鍵字自動強調（可手改）。
  先出 3–4 個預設樣式，全部過品質閘門。
- S-57 **音效規則表**：事件類型 → 音效（whoosh→甩鏡／推移、hit→閃白／重拍 zoom、pop→字幕／貼紙、riser→變速衝拍前、click→快門）；
  來源優先序：使用者資料夾 > Kenney CC0 包（下載腳本＋署名，不入庫或只入小樣本）> 程序合成。不和舊計畫衝突（舊計畫預設不加音效）。
- S-58 **節拍分層＋剪點密度**：`cut_density: low|mid|high`；剪點只落在重拍（或每 N 小節），拍點放 zoom／閃，段落交界換風格。
- S-59 **音樂裁長**：依小節／段落把歌裁到目標長度（含淡出或接尾段），給 3 個候選並標示接點；也可輸出「無音樂版＋拍點標記」供使用者在平台加授權音樂。
- S-60 **具名運鏡詞彙**：zoom／pan 動作命名（crash_in、crash_out、expo_in、smooth_in、whip、punch…）＋緩動（Penner BSD、spring 自寫），
  文件一張表；agent 用名字叫用。
- S-61 9:16 主體重構圖（spec-4 S-41 提前），依 spec-3 S-25 主體 sidecar。
- S-62 **先預覽後算繪**：proxy＋每個事件一張縮圖的 HTML 頁，使用者每鏡「保留／換掉」，只重算改到的鏡頭。
