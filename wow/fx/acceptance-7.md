## 共通規則（第一～六輪全部沿用，另加）
- **量測不信任建造者**：本卷每個「已知答案」由出題者的合成器決定，或由出題者以獨立量法（ffmpeg `signalstats` YAVG、`ebur128`、`astats`；numpy 自寫 Hasler–Süsstrunk、P1/P99、ΔE2000（`colour-science` 或自寫 CIEDE2000））從**輸出檔**重算。建造者 JSON 的數字只拿來比對誠實度：同一量測，建造者值與出題者值的差超出本卷容差 → 該條不過。
- **JSON 健全**：所有輸出 JSON 須能被 `json.loads(..., parse_constant=拒絕)` 讀入——不得出現 `NaN`、`Infinity`；未定義的量測寫 `null` 並附 `reason` 字串。
- **時間單位**：JSON 時間一律秒（float，≥ 3 位小數）或整數毫秒，文件寫明；格號另附。**±1 格** = 該片 fps 一格。
- **合成片解析度**：除非另寫，540×960、30 fps、H.264 yuv420p CRF 12（高品質，避免壓縮假影影響量測）；畫面都疊一層低振幅移動雜訊（σ=3，seed 固定）以免平面被編碼器抹平。音訊 48 kHz stereo。
- **可重現**：同輸入、同設定跑兩次 → JSON 除時間戳／耗時欄位外逐位元相同；PNG sha256 相同（或文件寫明 matplotlib 非決定性來源並改用固定後端使其相同）。
- **離線**：本輪所有量測與 lint 不得連網、不得呼叫付費 API（付費哨兵計數 = 0）；顯著圖、光流用 OpenCV／numpy 等本地方法；ML 美感分數模型**不得**出現（spec「不做」）。
- **舊計畫不退步**：第一～六輪 P-base、P-ramp、demo2/plan.json、demo3、demo4、第五／六輪基準計畫 → `--formats png` frames sha256 逐格相同於第七輪前 commit；本輪新功能全部是旁路（報告、lint、分鏡層），不改既有算繪結果，除非文件寫明且有旗標回復。

## S-80 taste_report.py（品味量測）—— 必要（理由：spec 第一原則「品味＝可量的結果」；沒有量測，其餘每條都只能憑感覺）
1. **M1 鏡長**：T-EQ 剪點全部 ±1 格、無多餘剪點；ASL／中位 1.000 s（±0.034）、CV ≤ 0.05。T-ALT：ASL、中位 1.250 s（±0.034）、CV 與 0.600（或 ddof=1 的 0.641，依文件）差 ≤ 0.03；JSON 附完整鏡長序列。**必要**
2. **M2 剪點對拍**：T-BEAT 每個剪點報出的偏差與真值差 ≤ 0.5 格；報「主要剪點 ≤ ±1 格」的比例 = 4/8 與真值一致。**必要**
3. **M3 起音密度**：A-ONSET 兩段密度 2／8（±10%）。**必要**
4. **M4 亮度曲線與爆點躍升**：T-DROP 峰位格 240 ±1、躍升 ≥ 40%（應 ≈ 529%；與出題者 signalstats 重算差 ≤ 5% 相對）；T-DROP-LIT 躍升 10%（±2%）且報「< 15%」警示；T-SAME 躍升 0（±1%）且不宣稱主峰。躍升公式寫在 JSON（分子分母取的區間）。**必要**
5. **M5 色彩度**：V-COLOR 遞增且與出題者實作差 ≤ 2%。**必要**
6. **M6 運動量**：V-MOTION 三速 ±15%，靜止段 < 0.3 px/格；JSON 寫明解析度（若降採樣量測，換算回原解析度）。**必要**
7. **M7 頻譜**：A-BAND 重心 ±5%、低頻占比 ±0.05；低頻截止頻率寫明。**必要**
8. **M8 響度**：A-FLAT／A-DYN 的 integrated LUFS、LRA、true peak、PLR（= TP − I）與出題者 EBU 量法差 ≤ 0.5 LU／dB；LRA 排序 A-DYN > A-FLAT；short-term 曲線（3 s 窗）時間軸對齊（A-DYN 每 4 s 階躍處的轉折 ±0.5 s）。**必要**
9. **M9 擁擠度**：V-CLUT-n Spearman = 1.0、n=320 ≥ 3× n=0；方法（邊緣密度或特徵擁擠度）與出處寫明。**必要**
10. **M10 顯著集中度**：V-SAL-C ≥ V-SAL-D + 0.15、C 重心誤差 ≤ 0.05 畫寬；定義（前 5% 像素占總顯著值比）照 §E。**必要**
11. **M11 靜默**：A-SIL 25%（±1%），門檻寫明。**必要**
12. **M13 對比範圍**：V-RAMP P1／P99 ±1.5；每格 P1、P99 序列輸出；P99 裁切比例（= 255 的像素比）輸出。**必要**
13. **M16 新奇度**：V-NOVEL 邊界 10、20 s ±0.5 s；段內無偽邊界（定義見素材表）。**必要**
14. **M12 事件時間表**：成片若有 manifest，JSON 輸出每個事件（時間、類型、配方、perceived）並與量測對照列（事件時間 ±1 格處是否量到 M4／M8 變化）。**加分**（理由：專業使用者驚豔；一般使用者看曲線就夠）
15. **M14 連續回應**：spec 未要求實作滑桿；若做，僅作選用。**無感**（理由：需真人，本輪不驗）
16. **喚起度代理 I(t)**：JSON 輸出 4 個分量的 z 序列、權重、平滑窗、I(t) 序列；出題者用 JSON 分量依 §E 公式 `smooth_2s(Σ w·z)` 重算，與 I(t) 最大差 ≤ 1e-3（以文件化平滑核）。預設權重 = 0.35／0.25／0.30／0.10。T-DROP 最高峰 ∈ [7.7, 9.0] s、峰前 2 秒低谷 ∈ [6.0, 8.0] s；前 3 名峰值與峰谷比輸出。**必要**
17. **權重可設**：`--weights` 或設定檔改權重 → JSON 記錄新權重、I(t) 改變；權重和 ≠ 1 的處理（正規化或報錯）寫明；負權重報錯。**必要**
18. **PNG**：有設計曲線（若提供）與量測 I(t) 疊圖、最高峰與峰前低谷有標記與時間文字、x 軸秒＋小節（有拍點時）；無設計曲線時只畫量測並標「無設計曲線」。出題者以 PNG 像素檢查：兩條曲線顏色不同（各自色彩像素 > 0.5% 畫面）、非空白。**必要**
19. **效能**：1080×1920、60 s、30 fps 片在開發機 ≤ 90 s 完成（可降採樣分析，文件寫明解析度，數字誤差仍守 1–13 條）。**加分**（理由：快才會每輪都跑；慢也能用）
20. 「報錯」：不存在的檔、非影片、無影像流 → 照共通規則報錯（非 0、無 traceback、不建 `--out`）。**必要**

## S-81 設計強度曲線 —— 必要（理由：沒有設計曲線，量測無從比較；spec 明定「相關 < 0.6 或峰偏 > 1 小節即修訂」）
1. **先有曲線**：處理方案（spec-4 S-37 treatment）含 `design_curve`（時間×強度，0–1，依音樂段落）；導演在沒有設計曲線時拒絕進入算繪（或自動依段落產生並標「自動」且寫入 treatment）。出題者刪掉 design_curve 跑導演 → 不得靜默產片。**必要**
2. **預算依曲線**：每段效果預算（spec-6 S-74 `perceived` 上限）與該段設計強度 Spearman ≥ 0.7（F-DESIGN 的計畫）。**必要**
3. **疊圖與相關**：F-DESIGN 三版：MATCH r ≥ 0.8 且不觸發；MISMATCH r < 0.6 → 觸發；SHIFT 峰偏 = 2 小節 → 觸發且原因寫「峰位偏差 2 小節」。出題者用 JSON 匯出的兩條曲線在文件化網格（例 10 Hz）重算 Pearson r，與報告值差 ≤ 0.02；峰偏以小節數報，對拍點表換算 ±0.25 小節。**必要**
4. **觸發的產物**：觸發時報告寫出「偏差最大的 2–3 段（起訖秒、設計值 vs 量測值、建議動作）」，不是只有一個 r。**必要**
5. 下一輪自動修訂後 r 提升（MISMATCH 經一輪修訂 r 至少 +0.2 或 ≥ 0.6）。**加分**（理由：閉環驚豔；但修訂可以人工做）

## S-82 大師訊號 lint —— 必要（理由：mastery-signals M1/M2/M5/M8/M18 是 spec 點名的五項）
1. **單一意圖**：treatment 有一句核心概念；storyboard 每個主要元素（鏡、配方、轉場、字幕段、音效族）有 `serves_core`（或同義）欄。夾具 SB-INTENT 缺 2 個 → lint 恰報那 2 個為「雜訊候選」並列元素 id；全有 → 0 條。內容空字串或與核心句完全相同的複製句 → 視為缺（防湊字）。**必要**
2. **焦點層級**：每鏡 M10 ＋ 與主體 sidecar 重疊率（顯著前 10% 區域 ∩ 主體遮罩 ÷ 顯著前 10% 區域）。夾具：主體遮罩在右上、顯著亮點也在右上 → 過；主體右上、畫面左下另有更亮的干擾物 → 報該鏡「焦點被搶」並附座標。**必要**
3. **刪減測試**：F-NOOP 中的無效效果被標「建議刪（無可量差異）」，附消融量測（mean |ΔY|、PSNR、ΔLUFS）；`zoom_punch` 不被標，而是進入「需成對比較」佇列（產生有／無兩支 2 s 小片與比較紀錄格式）。每個效果**類別**都有消融結果，覆蓋率 100%。**必要**
4. **最弱 2 秒**：F-WEAK 指出 [9, 11] 附近（重疊 ≥ 1.5 s），且不得指設計抽空的 [18, 20]；定義寫明（例：量測 I(t) 與設計曲線的負殘差最大的 2 s 窗；無設計曲線時退回 I(t) 最低且非設計谷）。報告附該 2 s 的抽格與原因量測（哪個分量低）。**必要**
5. **遠離 AI 平均**：同 brief 的 autoplan 預設版與導演版並排小片＋縮圖表；量測差異表（ASL、CV、色彩度、轉場族、LRA）至少 2 項超過「同一版重算雜訊」的 5 倍。評審一眼分得開由盲評紀錄佐證。**加分**（理由：spec 列入，但自動量只能佐證，真正判準是人眼；無此項不阻擋交付）

## S-83 剪輯文法 lint —— 必要（理由：§I 的剪輯文法是業餘與專業最可見的差別；每條須正反例）
每條 lint 都須輸出「第幾鏡／哪個剪點（秒＋格）、哪條規則、量測值與門檻、建議怎麼改」。門檻寫在設定檔可校準，預設值照下列。
1. **Rule of Six 優先序**寫進導演規則（references/director.md 或 taste.md）：情緒＞故事＞節奏＞視線＞2D 平面＞3D 空間；衝突時從低往高犧牲。lint 嚴重度依此排序（情緒／節奏類衝突時，視線類降為警告）。**加分**（理由：文件層；可量部分在下面）
2. **視線連續**：F-EYE 報（距離 ≈ 1.43 畫寬，門檻 0.30 畫寬）；F-EYE-OK 不報；F-EYE 在 storyboard 該剪點加 `rule_break: {rule: "eye_trace", reason: "<非空理由>"}` → 狀態變「已註明」，報告列出理由原文，不算錯誤。**必要**
3. **動作中切**：F-ACTION LATE 報、MID 不報；量測是剪點 ±3 格的 M6。**必要**
4. **鏡長變化**：T-EQ（CV ≈ 0）報「幻燈片感」，門檻預設 CV < 0.4（mood-pacing-arc「平」）；T-ALT（0.60）不報。**必要**
5. **爆點前抽空**：T-DROP 不報；T-DROP-LIT 報（峰前 2 s 無低谷：峰前 2 s I(t) 最小值 ≥ 峰值的 85%，或文件化門檻）。**必要**
6. **Mickey-mousing 上限**：F-MICKEY ALL 報、FEW 不報；指標＝配音效的動作事件數 ÷ 動作事件數，預設上限寫明且落在 (0.25, 1.0) 之間；喜劇風格包可宣告放寬（文件寫明）。**必要**
7. **J/L-cut 可用**：storyboard 剪點設 `audio_lead_ms: 500`（J）與 `audio_tail_ms: 500`（L），算繪後出題者以 astats／短時能量量得聲音轉換點在畫面剪點前／後 500 ms ±1 格；lint 能報出「此剪點為 J-cut」。**必要**（理由：spec 明列；不可量就只是文件）
8. 每條規則在 tests 中有正例（該報）與反例（不該報）各 ≥ 1，出題者全跑：正例全報、反例 0 誤報。**必要**

## S-84 風格系統（設計 token）—— 必要（理由：「規則一致」是 mastery M10；token 違規是最常見的業餘訊號）
1. `tokens.json` 格式文件化：色（color script 段落、1 個 LUT、膚色保護開關與範圍）、字（≤ 2 字型、字級比例、描邊／陰影規則）、轉場族（1 主＋1 強調）、質感（顆粒、光暈強度上限）、運鏡詞彙子集、音效族。風格包（spec-4 S-39）各自附一份 token。**必要**
2. **違規偵測**：F-TOK 恰報 4 類（第 3 字型每次出現、第 3 族與第 4 族轉場每個剪點、第 2 個 LUT），不多不少；F-TOK-OK 報 0。字型來源須含：字幕預設、單條字幕覆寫、效果參數內的字型（例：標題卡效果）——三處各藏一個第三字型，三處都抓到。**必要**
3. 運鏡用到 token 子集外的具名運鏡、質感強度超上限、音效族外的音效 → 各有正反例。**必要**
4. 轉場族歸屬來自 registry 卡片（spec-6 S-70）而非檔名猜測；每個 stable 轉場都有族標籤（覆蓋率 100%）。**必要**
5. 違規可用 `rule_break` 加理由豁免（同 S-83 第 2 條規則）。**加分**（理由：保留個性，對應 spec「lint 太嚴每支片一樣」）

## S-85 鏡頭配色一致 —— 必要（理由：「每鏡一個顏色」一看就拼接；§J Shot matching）
以 F-WB 量測（出題者 ΔE2000 自算，於解碼後 sRGB→Lab，D65）：
1. 匹配後 B 對 A：11 階灰平均 ΔE2000 ≤ **2.0**；全部色塊平均 ≤ **3.0**、最大 ≤ **5.0**；膚色塊 ≤ **3.0**；平均亮度差 ≤ 2%。匹配前的值（應 ≥ 8）同列在報告。**必要**
2. 參考鏡（A）不被改：A 鏡 frames sha256 與未匹配時相同。**必要**
3. **順序**：先匹配再套 LUT——同一計畫加 LUT 後，A_lut 與 B_lut 色塊平均 ΔE2000 ≤ 3.0；manifest／報告寫明處理順序。**必要**
4. 報告列每鏡 ΔE 與亮度差（匹配前／後）。**必要**
5. 匹配強度可調（0–1）；強度 0 = 原樣（sha 相同）。**加分**

## S-86 參考片校準 —— 必要（理由：spec 驚豔時刻的入口；同時是抄襲風險最高的一條）
1. **抽出目標**：`taste_target REF-FAST` 得 ASL 0.70 s（±0.05）、CV 0.50（±0.05）、LRA ≈ 9（與 EBU 量 ±0.5 LU）、事件密度、峰谷比、色彩度範圍（P10–P90）；REF-SLOW 同理。**必要**
2. **可重現**：同一參考片跑兩次（不同 `--out`、不同工作目錄）→ target JSON 除時間戳外逐位元相同；1–3 支參考片的合併規則（平均或範圍）文件化，參考片順序對調結果相同。**必要**
3. **不搬運內容**：輸出目錄（target、任何快取、報告）中：
   a. 不得有任何影像、影片、音訊檔（依副檔名與 magic bytes 雙查）；
   b. 不得有長度 > 1 KB 的 base64／hex 字串；
   c. 不得有可還原像素或取樣的陣列（任何數值陣列長度 > 2 000 或任一陣列 ≥ 該片格數 × 0.5 的逐格序列；逐格曲線須降採樣至 ≤ 2 Hz 或只存統計）；
   d. target JSON ≤ 64 KB；
   e. 以參考片校準做出的成片：逐格掃描 REF 指紋碼 → 0 格解出；與 REF 任一格 pHash 漢明距離 ≤ 6 的格數 = 0；音訊與 REF 掃頻指紋正規化互相關峰值 < 0.3。
   全部 a–e 通過才算過。**必要**
4. **導演照目標走**：同一份素材夾，分別以 REF-FAST、REF-SLOW 為目標做片 → 成片 ASL 依序（FAST 版 < SLOW 版），且各自與目標 ASL 差 ≤ 20%、CV 差 ≤ 0.15（素材長度不足時報告說明並給最接近值）。**必要**
5. 報告並列「目標 vs 成片」每個統計與差距。**加分**（理由：讓使用者看懂為什麼「節奏像那支」）

## S-87 使用者品味校準 —— 必要（理由：品味是使用者的；評審與使用者不一致時評審要被修正）
1. 每次交付給 3–5 組成對小片（每組只差一個維度：密度、色彩、字幕風格、轉場族），收「保留 A／換成 B／都可」；結果寫入品味檔（路徑文件化、人可讀 JSON、含日期與來源片）。**必要**
2. **持久且改變預設**：模擬 5 次選擇都偏「較高密度」→ 下一次 autoplan／導演預設的事件密度（出題者以 taste_report 量成片 M3／事件數）比校準前高，且預設值變化寫在報告「依你的品味檔：…」。選擇轉場族 X 兩次 → 下次 token 主轉場族預設 = X。刪掉品味檔 → 回到出廠預設（成片 sha 與校準前相同）。**必要**
3. **步幅有界**：單次選擇改變任一預設不超過文件化上限（例：密度 ±15%），避免一次點選翻轉全部。**必要**
4. **一致率**：品味檔記錄每組評審選擇與使用者選擇；一致率 = 一致數 ÷ 組數；< 70% 時該輪評審結論標「不作數」（沿用 spec-5 評估修正）。**必要**
5. 品味檔損毀（非 JSON、缺欄）→ 警告並回出廠預設，不崩潰、不覆寫原檔（另存 .bak）。**必要**
6. 可列出／重設：`taste show`、`taste reset`（或文件化同等指令）。**加分**

## S-88 詞彙吸收（taste.md）—— 必要（理由：導演（AI）實際讀的是這份；與程式不對齊就會說一套做一套）
1. `references/taste.md` 存在；每條：術語（原文）、白話、好的樣子／常見失敗、**對應量測（M 編號）或 lint 規則 id**、原出處 URL。出題者腳本：每條有 URL（100%）。**必要**
2. **雙向對齊**：程式中每條 lint 規則 id 都在 taste.md 出現；taste.md 中每個 lint id 都存在於程式（腳本比對，差集為空）。**必要**
3. SKILL.md 導演路線引用 taste.md；精簡：≤ 350 行或 ≤ 40 KB（只收導演會用到的）。**必要**（引用）／**加分**（長度）
4. 出處標「使用者 wow 詞彙檔」並保留原始 URL，不改寫成無來源斷言。**必要**

## S-89 測試 —— 必要
- `python -m unittest discover -s tests` failure 0；新測試以上表合成素材在測試內生成（不入庫大檔），覆蓋：M1–M13、M16 已知答案；I(t) 公式重算；每條 lint 正反例；token 違規；ΔE 匹配；參考片可重現與 3a–3e；品味檔持久與步幅；分鏡層（S-94）。需 ffmpeg 的測試在無 ffmpeg 時 skip 並寫理由，其他不得 skip；測試數多於第六輪結束時。

## 分鏡層（S-90..S-94；使用者追加「還有分鏡也能用的」）

### S-90 分鏡格式加入鏡頭語言 —— 必要（理由：分鏡是導演最便宜的決策點；欄位缺就無法 lint）
1. 擴充既有 `storyboard.json`（spec-4）與 references/planning.md shot table，**不另立格式**：舊 storyboard（第四輪 demo）仍可讀、轉 plan 結果 sha 不變。**必要**
2. 每鏡欄位：景別（EWS/WS/MS/CU/ECU 列舉）、角度、鏡頭感（廣角／標準／望遠）、運動（**單一值**，列舉 = S-60 具名運鏡 ∪ static/handheld）、構圖、畫面方向（左→右／右→左／中性，含軸線 id）、光線／色彩段（color script 段名）、聲音（段落、音效、J/L 偏移）、intent／recipe／perceived、轉場族、時長與拍點、why。JSON Schema 檔存在並以 `jsonschema` 驗證夾具；列舉外的值報錯。**必要**
3. 人看的分鏡表（md／html）由 JSON 生成，鏡數與欄位一致（腳本比對）。**必要**

### S-91 分鏡品味 lint（算繪前）—— 必要（理由：在花算繪與生成額度前就抓問題；spec 點名四類正反例）
夾具（出題者給規格，建造者實作於 tests）：
| 夾具 | 內容 | 期望 |
|---|---|---|
| SB-SAME5 | 同景別 MS 連 5 鏡 | 報「景別無變化」於第 3–5 鏡（或第 5 鏡起），建議換景別；SB-SAME5-OK（WS→MS→CU→MS→WS）不報 |
| SB-30 | 同主體連續兩鏡，景別相同、角度差 < 30° | 報 30° 規則；換景別或角度差 ≥ 30° → 不報 |
| SB-AXIS | 對話 A 在左、B 在右，第 4 鏡畫面方向反轉且無中性鏡／可見越軸運鏡 | 報越軸於第 4 鏡；中間插一個中性鏡或越軸運鏡 → 不報 |
| SB-2MOVE | 某鏡運動欄填兩個（push＋pan）或 recipe 內含第二個運鏡 | 報「一鏡兩運動」；Schema 層即拒絕陣列 |
| SB-QUIET | 設計曲線低的安靜段放 `impact` 重配方（perceived 超該段預算） | 報超預算＋建議移到 drop；安靜段只放輕配方 → 不報 |
| SB-CV | 8 鏡等長 | 報鏡長 CV 低 |
| SB-INTENT | 2 鏡缺 why／serves_core | 報該 2 鏡 |
| SB-TOK | 分鏡用了 token 外第 3 轉場族 | 報 token 違規 |
1. 上表每列正例全報、反例 0 誤報；每條報告含「第幾鏡、規則、建議怎麼改」三欄，建議為具體動作（例「第 4 鏡改 CU 或角度 ≥ 30°」），不是「請注意」。**必要**
2. **預測強度曲線**：由分鏡（鏡長、景別變化、運鏡、配方 perceived、音樂段落能量）算出，JSON 輸出公式與權重；與設計曲線疊圖並套 S-81 同一觸發規則（r < 0.6 或峰偏 > 1 小節）。F-DESIGN 的分鏡版 MISMATCH → 觸發。**必要**
3. lint 在 1 s 內完成 40 鏡分鏡（純 JSON，不讀影像）。**加分**（理由：即時回饋才會在寫分鏡時用）

### S-92 動態分鏡（animatic）—— 必要（理由：省時間與生成額度的關鍵；spec 要求「滿意才生成」）
1. **零素材可產**：分鏡沒有任何素材路徑時，每鏡依景別畫剪影卡（EWS 小人、CU 大頭等；卡上印鏡號、景別、運動箭頭、時長），套運鏡（push 就真的推）、轉場、配方（proxy 解析度）與音樂 → 輸出 mp4。出題者檢查：鏡數、每鏡時長 ±1 格；EWS 卡剪影面積占比 < CU 卡的 1/4；push 鏡首尾格剪影尺寸比 ≥ 1.1。**必要**
2. 有素材的鏡用素材縮圖／關鍵格，沒有的用剪影卡，混合不崩潰。**必要**
3. 動態分鏡自動跑 taste_report（S-80）並附疊圖。**必要**
4. 速度：30 s、40 鏡的動態分鏡在開發機 ≤ 30 s 產出。**加分**（理由：要快到可以反覆改）
5. 動態分鏡的時間軸與正式算繪一致：同分鏡轉 plan 正式算繪後剪點與動態分鏡剪點 ±1 格。**必要**

### S-93 生成提示詞由分鏡產出 —— 必要（理由：生成額度是錢；提示詞與分鏡脫節就白花）
1. 每鏡提示詞由欄位組出，含：景別、單一運動、主體動作、光線、時長、參考圖 id；腳本檢查每條提示詞含這 6 項（欄位或文字皆可，文件化）；提示詞內運動詞只有 1 個（以 S-60 運鏡詞彙表比對）。**必要**
2. 跨鏡角色一致：同角色的鏡都引用同一參考圖 id。**必要**
3. coverage：分鏡標 `coverage: true` 的段落產生 master＋MS＋CU 三條提示詞。**加分**（理由：專業剪輯彈性；一般用不到）
4. **閘門**：未過 S-91（有錯誤級違規）或未產生 S-92 動態分鏡時，生成指令拒絕或警告並要求確認；生成前仍照 SKILL.md 先問使用者——離線測試以假客戶端驗證：未確認前呼叫次數 = 0，付費哨兵 = 0。**必要**

### S-94 分鏡層測試 —— 必要
1. S-91 表中每列正反例都在 tests。**必要**
2. **預測 vs 實際**：至少 3 份分鏡（F-DESIGN MATCH 分鏡、SB-QUIET-OK、一份風格包範例）轉 plan 實際算繪（剪影卡素材亦可）後，taste_report 量測 I(t) 與分鏡預測曲線 Pearson r ≥ 0.6（出題者重算）。**必要**
3. 零素材動態分鏡測試（S-92 第 1 條）。**必要**
4. 提示詞欄位完整與一鏡一運動（S-93 第 1 條）。**必要**

## 看完整成品（第七輪；獨立評審原速有聲看成片＋讀品味報告，不看建造過程）
用一支 30–60 s 真實或擬真專案：先看第 N 輪成片與其品味報告，記下報告建議；再看依報告修改後的第 N+1 輪；並排原速有聲各看兩次。

| 項目 | Kano | 理由 |
|---|---|---|
| **報告點名最弱的 2 秒**（起訖秒、抽格、哪個量測低、為什麼），評審看片同意那 2 秒確實最弱（或在前 3 弱內） | 必要 | spec 驚豔時刻「指出最弱的 2 秒」；指錯＝量測不可信 |
| **建議可執行**：每條建議指到具體鏡／剪點／秒數，並寫具體動作（換哪鏡、加多長抽空、哪個效果刪），不是「增加張力」「更有節奏」 | 必要 | spec 未抵達：「報告一堆數字但不改變決策」 |
| **建議真的改變下一版**：N+1 版中被點名的段落有對應修改，且量測改善（該 2 s I(t) 殘差變小或 r 上升）；未點名段落不被亂動 | 必要 | 決策閉環是本輪價值 |

| **曲線與觀感一致**：評審自己的「這裡最爽／這裡最悶」與 I(t) 最高峰、最低非設計谷位置相差 ≤ 2 s | 必要 | 「曲線好看但片子仍平」是 spec 點名的失敗 |
| **說得出每個主要元素為什麼在那裡**（serves_core），評審抽 5 個元素讀理由，與畫面相符、不空泛 | 必要 | 單一意圖；理由編造＝失敗 |
| **刪減建議合理**：被建議刪的東西，拿掉後評審同意不輸 | 必要 | 克制 |
| **規則一致**：全片一套字（≤ 2 字型）、一族轉場（主＋強調）、無「每鏡一個顏色」 | 必要 | token、shot match |

## 不算通過的樣子
- 量測與出題者重算超出容差，或 JSON 有 NaN／Infinity；I(t) 無法由 JSON 分量重算。
- lint 正例不報或反例誤報；為讓 demo 通過而放寬門檻；豁免不需理由或可全域關閉而不在報告顯示。
- 最弱 2 秒指到設計好的抽空；建議空泛、不指位置。
- 參考片校準的輸出含任何影像／音訊／可還原陣列，或成片解出參考片指紋。
- 品味檔一次點選翻轉全部預設，或刪檔後無法回出廠預設。
- 分鏡 lint 只檢查格式不檢查文法；動態分鏡要素材才能產出；提示詞含兩個運鏡詞。
