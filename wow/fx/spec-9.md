# spec-9 — 導演的「工作台」：讓任何 AI 都能好好導演（2026-11-05）

來源：使用者 2026-11-05 `/wow 可以讓AI導演影片用的, 看還有沒有更好的做法?找到合適最好的做法做`。
前面已規劃導演的「手」（效果、轉場、字幕、音效、運鏡、交付，spec-1～8）、「品味」（spec-7）、「腦」（spec-4）。
第一性原則：AI 導演做得好不好，最後取決於**它能不能方便地看、查、試、比、改、記**——也就是它的工作介面。
現在是一堆各自參數不同的腳本；agent 要背 CLI、讀長文件、自己拼 JSON，錯一個欄位就重來，也看不到自己的作品。
競品趨勢（research/competitors.md）：剪映 Skills、Resolve 21 的 Claude/Codex 整合、Descript MCP——大家都在把剪輯能力**開放給外部 agent**。
推文原作者用的也是「Claude + MCP」。所以更好的做法是：**一個為 agent 設計的工作台**。

## 規格（trunk-based，每個 S 一個切片；排在 spec-8 之後、P3 導演整合之前或並行）
- S-110 **統一 CLI＋JSON 介面**：`vgs <動詞>`（analyze、plan、lint、preview、render、qa、taste、query-fx、query-cam、captions、music、intake、export），
  每個動詞 JSON 進、JSON 出（`--json`），共用錯誤格式（代碼、位置、建議修法、可用選項）；舊腳本保留並由 vgs 呼叫。
  每個輸入有 JSON Schema（`vgs schema <動詞>`），agent 先驗證再執行。
- S-111 **MCP 伺服器**：把 S-110 的動詞包成 MCP 工具（本機 stdio，零網路），工具描述精簡、參數有 schema 與範例；
  長工作回傳 job id 與進度；結果附可直接讀的縮圖路徑。Claude Code／Codex／其他支援 MCP 的 agent 都能用。
- S-112 **導演的眼睛（看的原語）**：`vgs look`：指定時間取格、事件前後聯絡表、A/B 並排、前後版本差異熱圖、
  音訊波形＋拍點＋事件疊圖、9:16 安全區疊圖；輸出小圖（預設 ≤ 1280 px、JPEG），讓 agent 用最少 token 看到該看的。
- S-113 **專案與版本**：專案資料夾＝素材索引＋處理方案＋分鏡＋計畫＋每次算繪的版本；`vgs diff v3 v4` 說出改了哪些鏡頭、事件、參數，
  附前後縮圖；`vgs revert`；每個決定保留理由（給下次修改與使用者回饋用）。
- S-114 **素材語意搜尋（選用）**：本機 CLIP 類模型（open_clip，權重須可商用；授權逐一核實）為素材庫建索引，`vgs find "夕陽下的人"` 回傳鏡頭與時間；
  沒裝模型時退回鏡頭卡的文字描述搜尋。導演用它從大量素材挑 B-roll。
- S-115 **交給專業剪輯軟體**：匯出 OpenTimelineIO（Apache-2.0）與 FCPXML，含剪點、轉場（盡量對應原生轉場，其餘以算好的片段替代）、字幕軌、音樂與音效軌、標記；
  在 Resolve／Premiere 能開（以 OTIO 驗證工具與可公開取得的 schema 檢查）。
- S-116 **導演評測基準**：固定 8–12 個題目（素材＋一句想法＋（可選）參考片＋音樂），每次導演能力改版就全跑一次，
  新舊版本成對盲評（雙順序）＋taste_report 數字＋使用者抽查一致率；結果入庫，退步就擋合併。這是讓導演「越來越好」而不是「越改越亂」的儀器。

## 驚豔時刻與未抵達的樣子
- 驚豔：在任何支援 MCP 的 AI 裡說一句「用這些素材做一支 20 秒的直式卡點片」，AI 就自己看素材、查效果、出預覽、看自己的預覽、改、交片，
  每一步都看得到；說「第三鏡換掉」只重做那一鏡；匯出到 Resolve 還能繼續精修。
- 未抵達：MCP 只是把腳本原封不動包起來（參數一樣難用）；看圖工具回傳大圖吃光 token；版本 diff 只是檔案差異；評測基準沒人跑。

## 不做
雲端服務、帳號系統、GUI 剪輯器（預覽 HTML 頁已足夠）、付費模型。

## 限制來源
- 題目數 8–12、圖片 ≤ 1280 px：agent 自訂儀器。MCP：公開協議。OTIO：Apache-2.0。
