# wow 輕量 第三輪 — 從「效果多」到「片子好」（2026-11-04）

來源：使用者 2026-11-04「wow 還有沒好的效果 看還有沒有更好的做法?用最好合適的做法做」。
第二輪已有約 25 個效果。第一性原則：爆款卡點片好看，靠的不是效果數量，而是**效果跟著主體走、聲音跟著畫面走、
大動作落在音樂的高潮、別人的節奏能套到自己的素材**。本輪補這四件事，再加兩個專業剪輯標準做法。
前提：第二輪通過審查後才開建；同一 worktree C:\Users\User\src\vgs-fx、分支 fx-framework。

## 主體感知（比「畫面中心」好）
- S-25 **主體追蹤資料**：對段落算一次主體遮罩（既有 background_remove，或快取的 BiRefNet 結果）→ 每格主體框、質心、面積，
  存成 sidecar（可快取、可手改）。ctx 提供 `ctx.subject`（框／質心／遮罩），沒有時退回畫面中心並在 manifest 記錄。
- S-26 現有幾何效果支援 `anchor: "subject"`：zoom_punch、radial_blur、shake、beat_bounce、2.5D 推鏡以主體為中心；
  `text`／貼紙可 `follow: "subject"`（跟著主體移動、不擋臉：放在主體框外側可用空間）。
- S-27 **主體轉場**（短影音最紅的兩種）：
  `subject_reveal`（下一鏡從前一鏡主體的剪影裡長出來，遮罩隨 p 擴張）；
  `match_cut`（把下一鏡縮放平移，讓兩鏡主體質心與大小對齊，再硬切或短溶接——「無縫轉場」）。

## 聲音跟著畫面（比「只有配樂」好）
- S-28 **程序合成音效層**：whoosh（濾波噪聲掃頻，配甩鏡／推移）、hit／impact（低頻衝擊，配閃白／重拍）、
  riser（上升音，配變速衝拍前）、shutter／click（配六邊形快門）、glitch（配故障轉場）。
  全部用 numpy 合成（零授權問題），效果或轉場可宣告預設音效，計畫可關閉／替換／調音量；
  與配樂混音（ducking 可選），峰值不爆（true peak ≤ −1 dBTP，qa_media 量）。也接受使用者自己的音效檔。

## 大動作落在高潮（比「每拍一樣」好）
- S-29 **音樂結構**：從能量與新奇度曲線找段落（intro／build／drop／outro）與 drop 時間點，寫進 beats.json（`sections`、`drops_ms`），
  計畫可寫 `on: "drop"`、`section: "build"`；選用 Beat This! 時重拍與段落對齊。附波形圖標出段落。
- S-30 **自動草稿**：`fx_autoplan.py --footage … --music …` 依段落產生第一版計畫：intro 少效果、build 漸強＋riser＋拍前變速、
  drop 上最重的轉場與閃白、outro 收尾；剪點落在重拍；每個決定附理由。這是給 agent／使用者改的起點，不是最終答案。

## 套用別人的節奏（比「只拆解」好）
- S-31 **模板轉移**：`fx_reverse` 的草稿可「換素材＋換音樂」：保留參考片的段落結構、事件類型與相對節拍位置，
  重新對齊到新音樂的拍點與段落、換成使用者的素材。只轉移結構（不搬運他人畫面、音樂、肖像），文件寫明。

## 兩個專業標準做法
- S-32 **LUT 調色**：讀 .cube（1D／3D，三線性插值，向量化），`lut` 效果可設強度；附 2–3 個程序產生的 LUT（不散布第三方 LUT）。
- S-33 **快速預覽**：`--proxy`（例 1/3 解析度、跳過選用模型、用快取）出低解析預覽＋每個事件一張縮圖的 HTML／圖片頁，
  讓「say yes or no」在幾秒內完成；正式算繪才跑全解析。量測 proxy 與正式的時間比。
- S-34 **幾何運動模糊**：shake／bounce／zoom／push 等快速幾何變換可選子格取樣運動模糊（`motion_blur: n`），避免頻閃感。

## 驗收與示範
- S-35 測試：每項離線測試（主體 anchor 用合成遮罩；音效以頻譜／包絡驗證；段落用合成「安靜→漸強→爆點」音軌；
  模板轉移來回測：A 片計畫轉到 B 音樂後事件仍在拍上）。全套不退步。
- S-展示3：同一批素材，「只用 S-30 自動草稿＋少量手改」做一支 15–30 秒成片，含音效層、主體轉場、drop 大動作；
  另做一支「模板轉移」：把 demo2 的節奏套到另一首曲子＋另一批素材。附「自動草稿 vs 最終」差異說明。看片由獨立評審判。

## 調查後不採用（之後候選）
- 人臉／人體關鍵點追蹤（MediaPipe 等）：主體遮罩已能涵蓋多數錨定需求，新增依賴不划算。
- 生成式音效模型、AI 配樂：授權與成本不明；程序合成已足夠覆蓋剪輯常用音效。
- GPU／GLSL：效能先靠 cv2 化（第二輪），不足再評估。

## 限制來源
- 範圍：agent 依使用者「找更好的做法」提出；四件事的排序是 agent 判斷（爆款好看的主因），可被評審質疑。
- −1 dBTP、15–30 秒：agent 自訂儀器。
