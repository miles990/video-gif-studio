- 第一輪「共通規則」全部沿用：技能 venv（有 cv2、**沒有 onnxruntime**）、ffmpeg 經 `VIDEO_GIF_FFMPEG`、「格時間」、亮度 Y、「報錯」定義（非 0、無 traceback、不建 `--out`、像素算繪前、牆鐘 < 3 s）、不得改 examples/、不得改本答案卷。

- 「1 格」= 計畫 fps（預設 25 → 40 ms）。因輸出可能插入 10 ms 拍點格，量「某時間 T 顯示的格」一律依 manifest 的累加 `durations_ms`。
- 「來源時間」= manifest 每格記錄的來源時間（S-15 要求）；本卷同時以像素反推（見 SYN-T）交叉驗證，兩者差 ≤ 1 個來源格（40 ms）。
- 「肉眼可分辨」量化：效果格與原圖格 RGB 平均絕對差 MAD ≥ 4/255，且 ≥ 2% 像素至少一通道差 ≥ 16/255。

## S-15 時間重映射層 —— 必要（「拍前慢、拍上衝」是本輪的核心手感；沒有就只是加濾鏡）
**常數／keyframes／包絡**（T 單段 `end_beat:4`，不補格 `interpolate:"none"`）：
| speed | 預期（來源時間對輸出時間的斜率，用 manifest 最小平方擬合；像素反推交叉驗證） |
|---|---|
| 未寫 | 斜率 1；frames 與第一輪同計畫 **sha256 逐格相同**（不偷改正常速度） |
| `"speed":1`（明寫） | 與「未寫」逐格 sha256 相同 |
| `"speed":0.5` | 斜率 0.5 ±5%；段長仍 2000 ms（輸出時鐘不變） |
| `"speed":2` | 斜率 2 ±5%；來源時間全落在整數來源格上 → 即使 `interpolate:"flow"`，每格都 **逐位元等於** 某來源格（方塊碼可讀、無補格） |
| keyframes `[[0,1],[1000,0.25],[2000,1]]` | 來源時間 = speed 的積分：t=1000 時來源時間 = 625 ms ±1 來源格；單調遞增 |
| 拍包絡 `{"on":"beats","decay_ms":200,"min":0.5,"max":2}` | 拍點後 200 ms 內斜率 > 拍前 100 ms 斜率；單調遞增 |

**P-ramp**：
1. 剪點（T→B）= 2000 ms 恰好（10 ms 規則），輸出總長與去掉 `ramp` 的同計畫相同（差 0 格）。**必要**
2. 來源時間在第一段內**嚴格遞增**（manifest 與像素反推皆然）；第二段從 B 的入點重新開始。**必要**
3. 慢段（文件寫明 ramp 的區間定義；量其中間 80% 的格）斜率 = 0.3 ±5%。**必要**
4. 衝段（`hit_ms` 對應的拍前／拍上區間，以文件定義為準）斜率 ≥ 1.5，且最後一格（2000 ms 前一格）的來源時間 ≥ 慢段結束時來源時間 + 衝段長 × 1.5。**必要**（「衝」量不到就沒有手感）
5. ramp 所需來源長度若超過素材：依文件「報錯（含段落位置與所需／可用 ms）」或「末格延長並在 manifest 標記」其一，實測一致；不得循環取格、不得 IndexError。**必要**
6. manifest 每格有 `source_ms`（或文件化等名）與實際補格方法；計畫中 `ramp` 鍵拼錯（`"rmap"`）、`slow` 超出範圍（例如 0 或 1.5）→ 第一輪 S-6 式報錯，含 `segments[0]`、錯字、有效範圍。**必要**
7. ramp 與既有效果時間一致：同計畫加 `flash_white` 於拍 4 → 峰值格仍在 2000 ms ±1 格（效果用輸出時鐘，不被來源時鐘拖走）。**必要**

## S-16 慢動作補格 —— flow 與 none/blend 選項：必要；RIFE 介面＋缺件報錯＋假引擎測試：必要；RIFE 實機：加分（主 agent 在 fx-optdeps 做）
素材 M，`"speed":0.25`，輸出取來源相位 0、0.25、0.5、0.75…；取相位 0.5 的格（k=4 與 5 之間，預期中心 x = 20+24·4+12+8 = 136）。
| 方法 | 預期（逐欄平均 Y 輪廓，y 全高） |
|---|---|
| `none` | 每格逐位元等於某來源格（重複格）；相位 0.5 格 = 來源格 4 或 5（文件寫明取前或最近） |
| `blend` | 相位 0.5 格出現兩條半亮條（各欄平均 Y ∈ [100,155] 的欄數 ≥ 24）——即「鬼影」基準 |
| `flow`（預設） | **單一條**：平均 Y ≥ 200 的欄連續一段、寬 16 ±3；其中心 = 136 ±2 px；Y ∈ [80,180] 的「半亮」欄數 ≤ 4（只容許邊緣）；比 blend 少 ≥ 80% |
| `rife`（假引擎） | 引擎收到的張量 shape [1,7,H',W']，H'、W' 補到 32 倍數，第 7 通道 = 0.5；輸出裁回 180×320；manifest 記 `rife` |
| `rife`（技能 venv，無 onnxruntime） | 報錯（定義同上），訊息含 `onnxruntime`、選用安裝方式（fx-optdeps 或選用 requirements 檔），**不得默默改用 flow**（若文件設計為退回，manifest 必須記錄實際方法與退回原因，且 stderr 警告） |
| 預設值 | 未寫 `interpolate` 時為 `flow`；接受值只有 none/blend/flow/rife，其他值報錯列出四個 |

- 補格只用在慢動作：speed=1 或 speed=2（整數相位）時，不論方法，輸出 = 來源格逐位元。**必要**
- 透明素材：C 以 speed 0.25 + flow → alpha=0 處隱藏 RGB 不漏出（輸出 alpha>0.05 的像素中，去預乘後接近洋紅的 = 0）；alpha 總和逐格變化 ≤ ±3%。**必要**
- 決定性：flow 兩次算繪 frames sha256 相同。**必要**
- 比較圖：`wow/fx/` 下有同一段 0.25× 的 none／blend／flow（＋rife 若實機有跑）並排圖，與每格耗時表（ms/格、解析度、機器）。**必要**；RIFE 實機欄位：**加分**。

## S-17 畫格歷史 —— 必要（殘影／拖影的基礎設施，echo 依賴它）
- 宣告：`@effect(history=N)`（或文件化等價）；ctx 取得「前 N 格」，文件寫明是**加效果前**的格還是**加效果後**的格（回饋），以及順序（最新在前或在後）。
- 用 fx-dir 自訂 `peek`：輸出 = ctx 提供的第 1 個歷史格（不存在時回傳原格）。在 A 單段算繪：第 k 格（k≥1，以輸出時鐘、不含插入的 10 ms 格之外的定義依文件）直條位置 = 第 k−1 格的直條位置 ±0 px。
- 段落邊界（P-base 的 A→B 硬切，echo `history:4`）：文件寫明「歸零」或「跨段」其一。
  - 歸零：B 第一格的輸出 = 不加 echo 的 B 第一格（MAE ≤ 1/255，區 R 無紅色殘留 R−B ≤ 0）。
  - 跨段：B 第一格區 R 的紅色殘留 = 文件公式的值 ±3/255。
- 時間軸第一格、N 大於已有格數：不崩潰，行為 = 文件寫明（補首格或缺格不算）。
- 決定性：整片算兩次 sha256 相同；`history` 不得讀到「未來」格（自訂效果記錄收到的歷史格的 t_ms 全部 < 當前 t_ms）。
- 記憶體：歷史只保留 N 格（文件寫明）。720p、N=8 的 echo 跑 90 格，行程峰值記憶體比 N=0 多 ≤ 12 × 單格 RGBA float32（約 177 MB）。**加分**（本機曾因記憶體中斷，但不是使用者會看到的東西）

| halftone | G 漸層：16×16 區塊平均 Y 與輸入差 ≤ 15%；輸出以網點呈現（每區塊內 Y 的雙峰：≥ 70% 像素在 ≤ 40 或 ≥ 215） |
| multi_cutout | 對 C：alpha>0.5 的連通區 = 3（或文件寫明的重疊方式下 3 個白邊輪廓可數）；每張卡有白邊（同第一輪 cutout 量測）；三張位移互不相同；隱藏洋紅 = 0 |
| 全部 | 吃拍包絡（至少強度參數）；P 像素畫在 `sampling:nearest` 下，幾何類（shake、spin、push、zoom_through、split_screen、kaleidoscope、mirror）輸出 alpha>0 像素顏色 ⊆ 原 4 色 **必要** |

## S-21 2.5D 視差（選用引擎）—— 介面＋假引擎離線測試＋缺件報錯＋授權防線：必要；實機 Small 模型：加分（主 agent 在 fx-optdeps 做）
素材 H，假深度引擎（方塊 1.0、背景 0.2；文件寫明「越大越近」），鏡頭微推＋平移預設，段長 2000 ms。
1. 視差：第 0 格與末格之間，近景方塊質心位移 |Δnear| ≥ 1.5 × 遠景紋理位移 |Δfar|（相位相關於方塊外區域）；|Δnear| ≥ 3 px。**必要**
2. 無洞：每格 alpha 全 255（H 不透明）；Y < 10 的像素 = 0（H 沒有純黑，出現即是黑洞）；方塊邊緣外 6 px 環帶內無「拉絲」：該環帶平均 Y 與遠景平均差 ≤ 25。**必要**
3. 尺寸：320×182 不是 14 倍數 → 正常算繪，輸出仍 320×182；引擎收到的 H、W 為 14 倍數（假引擎斷言）。**必要**
4. 快取：同圖同模型第二次算繪不呼叫引擎（假引擎呼叫次數 = 0）；改一像素或改模型名 → 重新呼叫。快取位置文件寫明且不在 examples/。**必要**
5. 模型不在（技能 venv 或模型路徑不存在）→ 報錯，訊息含模型檔名、放置路徑（`.runtime/models`）、`onnxruntime` 需求，並**建議改用 `beat_bounce`／`zoom_punch`**。**必要**
6. 授權防線：模型參數指向名稱含 `base`、`large`、`vitb`、`vitl`（大小寫不拘）的 Depth Anything 檔 → 依名稱拒絕，訊息說明 CC-BY-NC 不得使用、只接受 Small；**即使該檔存在也在載入前拒絕**（以空檔測試）。**必要**
7. 實機：fx-optdeps venv＋depth-anything-v2-small.onnx 對示範定格產生深度圖與視差片段，耗時記入 fx.md。**加分**

## 看完整成品（第二輪；評審肉眼判定，只看抽出的格、聯絡表與原速播放，不看建造過程）

## 不算通過的樣子
- 加了 speed／ramp 後剪點或總長改變；speed=1 的格與第一輪不同；補格偷偷用在正常速度。
- flow 中點偏離 > 2 px 或仍呈兩條半亮條；rife 缺件時 traceback 或默默改方法。
- history 讀到未來格、段落邊界行為與文件不符。
- text 出現豆腐框或缺字型時默默退回非 CJK 字型；字型檔入庫。
- 視差露黑洞／透明洞；Base/Large 模型可被載入；模型或字型檔入庫。
- 新效果在 preview 中與原圖分不出；效能數字缺或與實測差 > 30% 且不保守。
- 修改 examples/ 或本答案卷。
