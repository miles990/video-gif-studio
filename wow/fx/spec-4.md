# wow 輕量 第四輪 — AI 導演（2026-11-04）

來源：使用者 2026-11-04 `/wow ai 導演 會用合適最好的效果 分鏡 還有所有相關的, 看還有沒有更好的做法?找到適合最好的做法`，隨後「做」。
前提：第一～三輪的工具（fx_render、fx_reverse、品質閘門後的 stable 效果、主體 sidecar、音效、段落、autoplan、模板轉移、proxy）是導演的「手」；
本輪做導演的「眼睛、腦、品味與自我修正」。第三輪通過後開建；trunk-based，每個 S 一個切片，完成即 commit＋push。

## 核心情境
使用者只給「一句想法＋一堆素材（影片／圖片）＋（可選）音樂、平台」，導演產出：
處理方案（treatment）→ 分鏡表（每鏡：素材、入出點、景別／運鏡、效果、轉場、音效、字幕、對應的音樂段落與拍點、**為什麼**）
→ 2–3 個不同風格的版本 → 盲評挑出最好的 → 正式算繪＋QA 報告。使用者只需 say yes or no，或指著某一鏡說「這裡換掉」。

## 驚豔時刻與未抵達的樣子
- 驚豔：丟進 20 段手機素材＋一首歌，幾分鐘後拿到一支「像剪輯師做的」成片，分鏡表每一鏡都說得出理由；
  三個版本並排，盲評選出的那支確實最好；改一句話（「節奏再快一點」「結尾要溫柔」）就重出。
- 未抵達：效果堆砌（每拍都閃）、選到糊的／過曝的／主體被切掉的鏡頭、大動作沒落在高潮、轉場與內容無關、
  字幕擋臉、橫豎版本主體被裁掉、理由空泛（「增加節奏感」）、版本之間只是換濾鏡。

## 調查（2026-11-04）與選定做法
業界與研究的共同結構：鏡頭轉成結構化語言描述（L-Storyboard, arXiv 2505.12237）→ 規劃者寫分鏡 → 選鏡／修剪 → 對拍 →
評論者重看成片 → 修訂（EditDuet SIGGRAPH 2025、CineCut-Agent、agentic-video-editor 的「評分低於門檻就重試，最多 3 次」、
arXiv 2509.16811 的對拍代理）。我們採用這個結構，並在三處做得更好：
1. **確定性工具量「看得到的品質」，模型只做語意**：模糊、曝光、晃動、主體是否完整、運動能量都用程式量（可重現），
   不讓模型猜；模型（agent 自己看縮圖）只寫內容描述與情緒。
2. **多版本＋盲評選片**，不是單一版本自評：導演出 2–3 個風格明顯不同的剪法，由不知情的獨立評審成對盲評（雙順序）選出最佳，
   比「評論者打分數」更可靠（wow-judge 既有工具）。
3. **導演的規則可被機器檢查**：效果文法（何時用、強度、禁止組合、密度上限、多樣性）寫成 lint，分鏡表一出就先過 lint 再算繪。
所有程式自行實作；上述專案只吸收概念（多數未確認授權）。

## 規格
- S-36 **素材索引（導演的眼睛）**：`shot_index.py SRC… --out DIR`：自動切鏡（沿用 fx_reverse 剪點）、每鏡一張「鏡頭卡」JSON＋縮圖條：
  時長、清晰度（Laplacian 變異）、曝光（過曝／欠曝比例）、晃動（全域運動穩定度）、運動能量曲線、主體框與完整度（是否被畫框切掉，用 S-25 sidecar）、
  主色、亮度、是否適合定格（主體清楚＋靜止度高的格）、最佳入出點候選；以及給 agent 填的 `description`／`mood`／`tags` 欄位（agent 看縮圖後填寫，附「已看過」標記）。
  量測寫明方法與門檻；不用模型猜量得到的東西。
- S-37 **處方案與分鏡表格式**：`treatment.md`（一句話、觀眾、平台、長度、情緒曲線、風格）＋ `storyboard.json`
  （每鏡：shot_id、in/out、段落、拍點、景別、運鏡、效果、轉場、音效、字幕、理由），可直接轉成 fx_render 計畫（`storyboard_to_plan`）；
  另輸出人看的分鏡表（每鏡縮圖＋時間＋理由，HTML 或圖片頁）。整合既有 references/planning.md，不另立平行格式。
- S-38 **效果文法與 lint**：`references/director.md` 寫每個 stable 效果／轉場的「動機（什麼內容適合）」「強度建議」「段落」「禁止組合」；
  `fx_lint.py plan.json`：每拍事件密度上限、同拍禁止疊加（例 flash＋whip）、連續重複同一轉場上限、大動作需落在 drop／重拍、
  字幕不擋主體、效果不取代物理動作（沿用 SKILL.md 預設）、實驗中效果不得出現在正式版。違規報位置與修法。
- S-39 **風格包**：5–8 個導演風格（例：定格摳像卡點、電影感敘事、故障電子、日系清新、運動高燃、產品廣告、Vlog 輕快），
  每包＝效果／轉場白名單＋密度＋調色 LUT＋音效＋字幕樣式＋剪輯節奏規則；只用過品質閘門的 stable 效果；每包一張預覽。
- S-40 **選鏡與對拍**：依段落情緒曲線與鏡頭卡分數挑鏡（能量對能量、主體完整優先、避免連續相似鏡頭、開場 3 秒鉤子選最強鏡），
  入出點落在拍點且不切在動作中間（用運動能量找動作完成點）；每個選擇寫理由。
- S-41 **平台與重構圖**：`--aspect 9:16|1:1|16:9`：依主體 sidecar 自動重構圖（平滑追隨、不切頭、留標題安全區），
  字幕避開平台 UI 區（9:16 上下安全區）。
- S-42 **版本與盲評**：`director.py` 出 2–3 個版本（不同風格包或不同節奏），proxy 算繪後由獨立評審（不知版本來源，雙順序）成對比較，
  選出最佳再正式算繪；比較結果與理由入報告。使用者一句修改意見 → 只重做受影響的鏡頭（增量）。
- S-43 **評論與修訂迴圈**：正式版前跑 qa_media＋fx_lint＋導演檢查清單（鉤子、高潮、結尾、節奏變化、主體可讀、字幕可讀）；
  不過的項目自動修訂，最多 3 輪；仍不過如實列出。
- S-44 **缺鏡處理**：分鏡需要但素材沒有的鏡頭，列出「缺鏡清單」與建議（用既有素材替代／定格＋2.5D／用 Grok 等生成路線生成）；
  生成會花錢或額度時先問使用者（SKILL.md 既有規則）。
- S-45 **導演報告**：一頁看完：處方案、分鏡表縮圖、版本比較結果、為什麼這樣剪、QA 數字、可改的地方（「想要更快就改這裡」）。
- S-46 測試：鏡頭卡量測在合成素材上（糊／清楚、過曝、晃動、主體被切）分類正確；lint 每條規則正反例；storyboard→plan 來回；
  重構圖主體不出框；增量修改只重算受影響鏡頭。全套不退步。
- S-展示4：用 repo 內素材（examples/ 各作品＋自備的程序生成素材；不足時列缺鏡）＋一首 repo 內音樂，
  從「一句想法」到成片全自動跑一次，含 3 個版本與盲評結果、導演報告；再給一句修改意見重出。看片由獨立評審判，並與「第三輪 autoplan 直接出片」成對比較，導演版要勝出。

## 不做
人臉辨識／身分、語音轉錄與口播剪輯（之後候選）、雲端或付費模型呼叫（需使用者同意）、多機位同步。

## 限制來源
- 版本數 2–3、修訂 ≤ 3 輪：參考 agentic-video-editor 的重試上限，agent 自訂。
- 「導演版要勝過 autoplan」：agent 自訂的標竿條件（沒勝過＝導演層沒有價值）。
