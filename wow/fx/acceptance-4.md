## 共通規則（第一～三輪全部沿用，另加）
- 技能 venv（有 cv2、無 onnxruntime）、ffmpeg 經 `VIDEO_GIF_FFMPEG`、「格時間」、亮度 Y、「報錯」定義（非 0、無 traceback、不建 `--out`、像素算繪前、牆鐘 < 3 s）、不得改 examples/、不得改本答案卷、離線測試不下載／不讀真實權重。
- **量測不信任建造者**：本卷所有「主體位置／是否被切／是否糊」的判定，以合成素材的**已知真值**（生成參數）或出題者的獨立量法（顏色門檻質心、Laplacian 變異參考實作）為準，不以建造者 sidecar 或鏡頭卡自報值為準。
- **無付費呼叫**：所有離線測試與 S-展示4 的自動流程在下列「付費哨兵」下執行：`GROK_API_KEY`／`XAI_API_KEY`／`FAL_KEY`／`FAL_API_KEY`／`OPENAI_API_KEY` 全部未設定，並以哨兵（monkeypatch `grok_client`、`fal_video`、`urllib`／`requests`／`socket.create_connection`，任何呼叫即記錄並 raise）包住；哨兵計數必須 = 0。只有使用者在對話中明確同意的那一次生成例外，且須在報告寫明。
- **模型只做語意**：鏡頭卡中能量測的欄位（清晰度、曝光、晃動、運動能量、主體完整度、主色、亮度、定格候選、入出點候選）必須由程式產生，同輸入兩次逐位元相同；`description`／`mood`／`tags` 才由 agent 填，且帶「已看過」標記（例 `reviewed_by`、`reviewed_thumbs` 指向實際存在的縮圖）。未看過就填 = 不過。
- 「1 拍」、「±1 格」、音訊量測定義同第三輪。
- 舊計畫不退步：第一～三輪的 P-base、P-ramp、demo2/plan.json、第三輪 demo3 plan.json → frames **sha256 逐格相同**於第四輪前（以第三輪結束 commit 對照）。導演層只新增，不得改動既有效果的輸出。

## 合成素材（第一～三輪全部照用；以下新增，全部由出題者／測試程式 numpy 產生，不入庫真實影片）
基底畫面 BASE(seed)：640×360、25 fps、50 格（2.0 s）、背景 = 32 px 棋盤 (90,90,90)/(140,140,140) 疊 seed 決定的低頻色塊（讓清晰度有紋理可量）；主體 = 實心圓半徑 40、色 (240,200,40)，附遮罩序列。每類用 seed 0..4 各產 5 支（共「類別 × 5」），供分類正確率統計。

| 代號 | 內容（相對 BASE） | 真值標籤 |
|---|---|---|
| V-SHARP | BASE，主體圓心 (320,180) 靜止 | 清楚、曝光正常、穩定、主體完整、低動能 |
| V-BLUR | V-SHARP 每格 Gaussian σ = 3.0 px | 糊 |
| V-BLUR-M | V-SHARP 每格 Gaussian σ = 1.2 px | 邊界例（文件門檻須明確把它判到某一側，並寫明理由；不計入正確率，只檢查確定性） |
| V-OVER | V-SHARP 亮度 ×2.2 後截到 255（≥ 40% 像素 Y ≥ 250） | 過曝 |
| V-UNDER | V-SHARP 亮度 ×0.15（≥ 40% 像素 Y ≤ 16） | 欠曝 |
| V-SHAKE | V-SHARP 每格整體平移 (dx,dy) ~ 均勻 [−14,14] px（seed），邊緣以反射補 | 晃 |
| V-PAN | V-SHARP 每格等速平移 +6 px/格（運鏡，不是晃） | 穩定（有運鏡）——晃動量法須區分「平滑運鏡」與「手震」 |
| V-CUT | 主體圓心 (20,180)（左半圓出框） | 主體被切 |
| V-CUT-TOP | 主體圓心 (320,10)（上半圓出框，「切頭」） | 主體被切 |
| V-NOSUBJ | 無主體、無遮罩 | 無主體（完整度欄位 = null／文件化值，不得是「完整」） |
| V-HIGH | 主體圓心 x = 60 + 10i（每格 10 px）＋背景每格亮度擺動 ±20 | 高動能 |
| V-LOW | 主體圓心 x = 300 + 0.5i | 低動能 |
| V-ACT | 主體 0–19 格靜止於 x=100，20–34 格以 24 px/格衝到 x=460，35–49 格靜止 | 動作段 [20,34]；動作完成點 = 第 35 格 |
| V-DUP | V-SHARP 加高斯雜訊 σ = 2/255（near-duplicate） | 與 V-SHARP 相似（相似度 ≥ 文件門檻） |
| V-MULTI | V-SHARP(2 s) ＋ V-HIGH(2 s) ＋ V-UNDER(2 s) 硬接成一支 6 s mp4 | 剪點真值 2000、4000 ms |
| V-TALL | 360×640 直式版 V-SHARP（主體在 (180,320)） | 直式來源 |
| V-WALK | 640×360、100 格（4 s），主體圓心 x = 40 + 5.6i、y = 180 + 30·sin(2πi/50) | 重構圖追隨 |
| IMG-STILL | 單張 PNG（V-SHARP 第 0 格） | 圖片素材 |
| QBD.wav、QBD-beats、FLAT.wav、B2.wav | 第三輪定義 | 音樂 |

基準指令（名稱以建造者為準）：

## S-36 素材索引（導演的眼睛）—— 必要
1. **切鏡**：`shot_index.py D/V-MULTI.mp4` → 恰 3 張鏡頭卡；剪點 = 2000、4000 ms ±1 格；沿用 fx_reverse 的剪點偵測（同輸入時剪點與 `fx_reverse.py` 的剪點相同 ±0 格，或文件寫明差異與理由）。**必要**
2. **鏡頭卡欄位齊全**：每張 JSON 含 時長、清晰度、曝光（過曝比例、欠曝比例）、晃動、運動能量曲線（每格一值，長度 = 格數）、主體框序列與完整度、主色、平均亮度、定格候選（格號＋分數）、入出點候選、`description`／`mood`／`tags`（初值為空或 null）、已看過標記、縮圖條路徑（檔案存在、≥ 3 張）。欄位缺一 = 不過。**必要**
3. **方法與門檻寫明**：references/director.md（或 fx.md）對每個量測寫：方法（例 清晰度 = 灰階 Laplacian 變異，於固定解析度縮放後量）、門檻數值、單位、量測解析度。改門檻須是設定值不是散落常數。**必要**
4. **分類正確率**（每類 seed 0..4 共 5 支，出題者以鏡頭卡的判定欄位或「欄位 vs 文件門檻」判定）：

| 判定 | 正例 | 反例 | 要求 |
|---|---|---|---|
| 糊 | V-BLUR ×5 | V-SHARP ×5、V-PAN ×5 | 15 支全對（100%）；且清晰度數值 V-BLUR 中位數 ≤ V-SHARP 中位數的 25% |
| 過曝 | V-OVER ×5 | V-SHARP、V-UNDER 各 ×5 | 100% |
| 欠曝 | V-UNDER ×5 | V-SHARP、V-OVER 各 ×5 | 100% |
| 晃 | V-SHAKE ×5 | V-SHARP ×5、**V-PAN ×5** | 15 支 ≥ 14 支對（≥ 93%）；V-PAN 判「晃」= 該項不過（平滑運鏡不是手震，這是專業剪輯師的基本分辨） |
| 主體被切 | V-CUT ×5、V-CUT-TOP ×5 | V-SHARP ×5 | 100% |
| 動能高／低 | V-HIGH ×5 vs V-LOW ×5 | — | 每支 V-HIGH 的平均能量 > 每支 V-LOW 的 3 倍 |
| 相似鏡頭 | V-DUP vs V-SHARP（同 seed） | V-SHARP vs V-HIGH | 相似分數正例 ≥ 門檻、反例 < 門檻，5/5 |

   全表合計正確率 ≥ 97%，且「糊」「主體被切」兩項必須 100%（這兩項選錯直接進成片）。**必要**
5. **無主體**：V-NOSUBJ → 完整度欄位為文件化的「無主體」值（例 null + `subject: "none"`），不崩潰、不判成完整。**必要**
6. **定格候選**：V-ACT 的定格候選最高分格 ∉ [20,34]（動作中糊的格不得當定格）；V-SHARP 有 ≥ 1 個候選。**必要**
7. **入出點候選不切在動作中**：V-ACT 的出點候選中 ≥ 1 個在第 35 格 ±2 格（動作完成點）；候選中落在 [22,32] 的 = 0。**必要**
8. **圖片素材**：IMG-STILL 產 1 張卡，時長欄位文件化（例 null 或「靜態」），晃動／運動能量為 0 或 null，不崩潰。**必要**
9. **決定性**：同輸入兩次，所有量測欄位逐位元相同（description 等語意欄除外）。**必要**
10. **已看過標記不得偽造**：`description` 非空而「已看過」標記缺失或指向不存在的縮圖 → `shot_index.py --check`（或 fx_lint／director 的前置檢查）報錯。**必要**
11. 牆鐘：10 支 2 s 640×360 素材索引 ≤ 20 s（無 GPU）。**加分**
12. 縮圖條人眼可讀（每格標時間與分數）。**加分**

## S-37 處方案與分鏡表格式 —— 必要
1. `treatment.md` 必含標題或欄位：一句話、觀眾、平台、長度、情緒曲線、風格（6 項，grep 皆命中）。情緒曲線須對應音樂段落（intro／build／drop／outro 或文件化集合），不是只寫形容詞。**必要**
2. `storyboard.json` 每鏡必含：shot_id（指向鏡頭卡）、in、out、段落、拍點、景別、運鏡、效果、轉場、音效、字幕、理由。缺欄 → 文件化的 schema 驗證報錯，列缺的欄位與鏡號。**必要**
3. **與 planning.md 整合**：planning.md 指向導演格式（不另立平行格式）；分鏡表欄位涵蓋 planning.md 要求（起訖、可見動作、景別／運鏡、敘事目的、轉場與連續性、效果／音樂提示、已有 vs 缺的素材）；音樂提示區分「分析得到」與「估計」。**必要**
4. **storyboard → plan 來回**：
   - `storyboard_to_plan(sb)` 產生的 plan 通過 `fx_render.py --validate`，且可直接算繪。**必要**
   - plan 的段落（剪點 ms、素材、入出點）與 sb 逐一相同 ±0 ms；效果／轉場／音效事件的類型與時間與 sb 相同 ±0 ms（拍點由 beats.json 解析，manifest 記錄解析值）。**必要**
   - 若提供反向 `plan_to_storyboard`：sb → plan → sb' 後，sb' 與 sb 在上述欄位相等（理由、字幕原文逐字相同）；plan → sb → plan' 時 plan' 與 plan JSON 正規化後相等。若不提供反向，sb → plan 兩次位元相同，且 plan 中保留每鏡 shot_id 與理由（可追溯）。**必要**（其一）
   - 總長：Σ(out−in)（換算速度後）= 計畫總長 ±1 格；與 treatment 長度 ±1 拍。**必要**
5. **人看的分鏡表**：HTML 或 PNG 頁，每鏡一列：縮圖（≥ 1 張，從入點附近取）、時間、段落、效果／轉場、字幕、理由；鏡數 = storyboard 鏡數；HTML 相對路徑全部存在。**必要**
6. **理由不空泛**：每鏡理由 ≥ 1 條「具體依據」——引用量測值或鏡頭卡欄位（清晰度／動能／主體）、或段落／拍號、或敘事功能（鉤子／高潮／收尾）。黑名單（只出現以下而無其他依據即不過）：「增加節奏感」「更有張力」「提升質感」「讓畫面更豐富」「吸睛」。違規數 = 0。**必要**
7. 分鏡表可在不讀 JSON 的情況下讓人指著某一鏡說「換掉」（每鏡有可引用的編號）。**加分**

## S-38 效果文法與 lint —— 必要
1. `references/director.md`：每個 stable 效果與轉場（以 `fx_render.py --list` 中 stable 者為準，數量逐一對上，缺一 = 不過）有：動機（什麼內容適合）、強度建議（數值範圍）、適用段落、禁止組合。**必要**
2. `fx_lint.py plan.json`：違規 → 非 0 結束、每條違規列 規則 id、時間（ms 與拍號）、鏡號、修法建議；無違規 → 0。輸出可 `--json`。**必要**
3. **每條規則正反例**（出題者各寫最小計畫；每條「正例」必報該規則恰 ≥ 1 次、「反例」該規則 0 次）：

| 規則 | 正例（必須報） | 反例（不得報） |
|---|---|---|
| 每拍事件密度上限（文件值 N） | 同一拍放 N+1 個效果 | 同一拍恰 N 個 |
| 同拍禁止疊加 | 拍 8 同時 `flash_white`＋`whip_pan` | 拍 8 `flash_white`、拍 9 `whip_pan` |
| 連續重複同一轉場上限（文件值 K） | K+1 個連續 `whip_pan` 轉場 | K 個連續、第 K+1 換成 crossfade |
| 大動作需落在 drop／重拍 | QBD 上把最重轉場放在 5250 ms（非重拍、非 drop） | 放在 8000 ms（drop） |
| 字幕不擋主體 | S 素材上字幕框覆蓋主體遮罩 ≥ 20% | 字幕在主體框外，重疊 0 |
| 效果不取代物理動作 | 用 `zoom_punch`／`shake` 假裝角色出拳（計畫宣告 `replaces_action` 或文件化等價標記），或在主體靜止鏡上以位移效果偽造「走動」 | 角色真實動作鏡上加 zoom_punch 強調 |
| 實驗中效果不得出現在正式版 | 正式（非 proxy／非 draft）計畫含任一非 stable 效果 | 同效果只出現在 `--proxy`／草稿計畫（或文件化的 preview 模式）時不報，或報為 WARN 而非 ERROR |
| 密度弧線（若實作） | intro 每秒事件數 ≥ drop | intro < build < drop | 
| 多樣性（若實作） | 全片只用 1 種轉場且 ≥ 6 次 | ≥ 3 種 |

   前 7 條 **必要**；後 2 條 **加分**（spec 提到「多樣性」，有就更好）。
4. **修法可用**：對前 7 條正例套用 lint 給的修法（若有 `--fix`，直接跑；否則按建議手改）後重跑 lint = 0 違規，且未新增其他規則違規。**必要**（`--fix` 本身 **加分**）
5. **第三輪 autoplan 與 demo3 計畫**跑 lint：若有違規，須在報告說明是 lint 太嚴還是 autoplan 的問題（不得默默放寬規則讓它過）。**必要**
6. lint 牆鐘 ≤ 1 s（100 事件計畫）。**加分**

## S-39 風格包 —— 必要
1. 數量 5–8；每包含：效果／轉場白名單、密度（每秒事件上限或段落密度）、調色 LUT（程序產生或 `none`，不得第三方）、音效設定、字幕樣式（字型、大小、位置規則）、剪輯節奏規則（平均鏡長或每鏡拍數範圍）。缺欄 = 不過。**必要**
2. **只用 stable**：所有白名單項 ∈ `--list` 的 stable 集合；包內引用實驗效果 → 載入時報錯（含效果名與包名），不是默默略過。**必要**
3. **每包一張預覽**：PNG 或 GIF 存在，由同一合成素材＋同一音樂算繪（便於比較）；預覽可重現（文件一行指令）。**必要**
4. **包之間真的不同**：任兩包的 (a) 白名單 Jaccard ≤ 0.6，或 (b) 平均鏡長相差 ≥ 40%，或 (c) LUT 不同且密度差 ≥ 30%——至少滿足其二。只差 LUT = 不過。**必要**
5. **每包都能過 lint**：用 V-* 素材＋QBD 以每個包出一版計畫 → `fx_lint` 0 違規。**必要**
6. 自訂包：使用者可放一個 JSON 包到文件化目錄並被載入；格式錯 → 報錯含欄位名。**加分**

## S-40 選鏡與對拍 —— 必要
素材池 P40 = {V-SHARP-0, V-BLUR-0, V-OVER-0, V-UNDER-0, V-SHAKE-0, V-CUT-0, V-CUT-TOP-0, V-HIGH-0, V-LOW-0, V-ACT-0, V-DUP-0, V-PAN-0}，音樂 QBD.wav，9:16、15 s。
1. **不選壞鏡**：選中的鏡頭中 V-BLUR／V-OVER／V-UNDER／V-SHAKE／V-CUT／V-CUT-TOP 出現次數 = 0（池中有可替代的好鏡）。**必要**
2. **鉤子**：0–3000 ms 內的鏡頭 = 池中「鉤子分數」最高者（文件定義，例 動能×清晰度×主體完整度），且該鏡清晰、主體完整。理由欄寫「鉤子」並引用分數。**必要**
3. **能量對能量**：drop 段（8000–14000 ms）所用鏡頭的平均運動能量 ≥ intro 段的 2 倍；V-HIGH 出現在 drop 段而非 intro。**必要**
4. **避免連續相似**：V-SHARP 與 V-DUP 不相鄰（中間至少隔 1 鏡），或只選其一。**必要**
5. **剪點在拍上**：每個剪點 ∈ beats_ms ±10 ms；段落邊界 ∈ downbeats ±10 ms。**必要**
6. **不切在動作中間**：選到 V-ACT 時，其出點不落在動作段 [20,34] 格內（以來源格號計）；若選擇在動作完成點出鏡，出點 = 第 35 格 ±2；入點不落在動作中間除非理由寫明「動作剪接（cut on action）」且下一鏡延續動作。**必要**
7. **每個選擇有理由**：每鏡理由引用鏡頭卡欄位值（數字）或段落／拍號；並列出「未選的候選與原因」至少 1 筆（例 「V-BLUR-0：清晰度 12 < 門檻 80，淘汰」）。**必要**
8. **決定性**：同輸入兩次 storyboard 位元相同（或只差文件化時間戳）。**必要**
9. 素材不足時（池只有 2 支好鏡、要 15 s）：重複使用須換入點或換景別（文件化：裁切推近／定格），並在理由說明；不得默默重複同一段 ≥ 2 次。**加分**

## S-41 平台與重構圖 —— 必要
輸入 V-WALK（16:9, 640×360），`--aspect 9:16`（輸出裁切框 202×360 或文件化尺寸再放大）。
1. **主體不出框**：以出題者顏色門檻量測每格主體 bbox（圓 r=40），bbox 完整在裁切框內的格數 ≥ 98%；任一格出框面積 ≤ 主體面積的 10%。**必要**
2. **平滑**：裁切框中心 x 的相鄰格位移 ≤ 12 px（640 寬尺度）；二階差（加速度）≤ 4 px/格²；無「只在出框時才跳一下」的階梯（位移序列中 > 8 px 的跳動 ≤ 2 次）。**必要**
3. **不切頭**：V-CUT-TOP 類情形以外，主體 bbox 上緣到裁切框上緣 ≥ 主體高的 10%（頭頂留白）≥ 95% 格。**必要**
4. **1:1 與 16:9**：V-WALK `--aspect 1:1` 同 1–2 條（框 360×360）；V-TALL（直式）`--aspect 16:9` 見另卷（不得 traceback；文件寫明補邊或放大策略）。**必要**
5. **無主體退回**：V-NOSUBJ 9:16 → 中心裁切或文件化策略，manifest 記錄 fallback 原因。**必要**
6. **字幕避開平台 UI 區**：references/director.md 寫明各平台安全區（至少 9:16：上 ≥ 10% 高、下 ≥ 20% 高、右 ≥ 10% 寬為 UI 區；數值以建造者文件為準但不得小於此）。每格字幕墨（alpha > 0.5 或與無字版差 > 16/255）**100%** 在安全區內；字幕墨與主體遮罩重疊 ≤ 2%（沿用第三輪 follow 量法）。**必要**
7. **標題安全區**：片頭標題（若有）同樣在安全區內，且距安全區邊 ≥ 2% 寬。**必要**
8. 重構圖後仍可以 anchor／follow：zoom_punch `anchor:"subject"` 在 9:16 輸出上主體質心不動 ±2 px（輸出座標）。**加分**

## S-42 版本與盲評 —— 必要
1. `director.py … --versions 3` 產出 3 個版本目錄，各有 storyboard、plan、proxy 成片；版本來自不同風格包或不同節奏（manifest 記錄）。`--versions` 範圍 2–3，其他值報錯。**必要**
2. **版本真的不同**（任兩版都要滿足以下至少 2 項）：鏡頭順序（shot_id 序列）正規化編輯距離 ≥ 0.3；剪點時間有 ≥ 30% 相差 ≥ 1 拍；效果＋轉場類型集合 Jaccard ≤ 0.6；平均鏡長相差 ≥ 25%。只換 LUT／濾鏡 = 0 項 → 不過，且系統須自行偵測並拒絕（見另卷）。**必要**
3. **盲評隔離**：給評審的輸入（檔名、目錄名、提示文字、影片 metadata、燒入畫面的字）中，grep 風格包名稱、`version_`、`autoplan`、`director` 等來源字樣 = 0 筆；版本以隨機代號（A/B/C，代號對應存在評審看不到的檔案）呈現。**必要**
4. **雙順序**：每一對都以 (X,Y) 與 (Y,X) 各評一次；3 版 → 6 筆評審紀錄；每筆含：呈現順序、勝者、理由（≥ 1 句具體指向畫面時間或鏡號）。兩順序結論相反 → 記為平手，不得取其一。**必要**
5. **選出最佳**：依文件規則（例 勝場數，平手規則寫明）選出；選擇與紀錄一致（出題者重算勝場可得同一結果）。全部平手時的規則寫明（例 取 lint 違規最少／qa 最佳，並報告「盲評無區分」）。**必要**
6. 只有勝出版本做正式算繪；其他版本只有 proxy（以檔案存在與牆鐘證明）。**必要**
7. **增量修改**：8 鏡 storyboard，`--revise --note "結尾要溫柔"`：
   - 系統把意見映射到受影響鏡頭（outro 段的鏡）並在報告列出映射與理由。**必要**
   - 重新算繪的鏡數 = 受影響鏡數（log／manifest 計數器證明），未受影響鏡的 frames sha256 與修改前逐格相同。**必要**
   - 改動確實「溫柔」：outro 段事件密度下降或轉場改為溶接類、閃白類事件 = 0、音效強度不升。**必要**
   - `--note "第 3 鏡換掉"` → 只換第 3 鏡素材，其他鏡 sha 不變；新鏡仍過 S-40 1–6。**必要**
   - `--note "節奏再快一點"` → 平均鏡長下降 ≥ 15%，剪點仍在拍上；此為全域修改，允許全部重算但須報告「全域」。**必要**
   - 增量牆鐘 ≤ 全部重算的 50%（8 鏡改 2 鏡時）。**加分**

## S-43 評論與修訂迴圈 —— 必要
1. 正式版前跑：qa_media、fx_lint、導演檢查清單（鉤子、高潮、結尾、節奏變化、主體可讀、字幕可讀），每項 PASS/FAIL 與量測值寫入報告。檢查清單每項有可機器判定的定義（文件寫明）。**必要**
2. **注入失敗**：給一個鉤子鏡是 V-BLUR、drop 放在 build 中段、字幕擋主體的 storyboard → 迴圈自動修訂，每輪記錄：失敗項、修改了什麼、修改後結果。**必要**
3. **最多 3 輪**：修訂輪數 ≤ 3（計數器）；第 1 輪即全過時停在 1 輪（不得多跑）。**必要**
4. **修不好就如實列出**：構造一個無法修好的情況（例 素材全部是 V-BLUR，見另卷）→ 3 輪後停止、報告列出仍 FAIL 的項目與原因，結束碼或報告狀態明示「未全過」；不得把 FAIL 改寫成 PASS、不得放寬門檻。**必要**
5. **不震盪**：同一項在第 n 輪修好、第 n+1 輪又壞 → 報告標出；修訂不得讓已 PASS 的項變 FAIL（若發生須回退該修改）。**加分**

## S-44 缺鏡處理 —— 必要
1. 分鏡需要但池中沒有的鏡（例 想法「海邊日落」而池中只有 V-* 合成鏡；或 storyboard 指定 `need: "close-up of hands"`）→ 輸出「缺鏡清單」（JSON＋報告段落）：鏡號、需要什麼、為什麼需要、建議（用既有素材替代＝指名 shot_id／定格＋2.5D＝指名來源格／生成路線＝Grok 等，並標「會花錢或額度」）。**必要**
2. **不付錢**：整個流程付費哨兵計數 = 0；生成建議只寫出待確認的提示詞與預估成本／額度欄位，不建 provider job。**必要**
3. 有替代可行時預設用替代並在理由寫明；使用者明確同意生成前，正式版不含任何生成素材。**必要**
4. 缺鏡清單在人看的分鏡表中以明顯標記呈現（例 灰框＋「缺」）。**加分**

## S-45 導演報告 —— 必要
一頁（HTML 或 PDF／PNG 單頁；HTML 相對路徑全部存在）必含以下段落（grep 標題或 id 皆命中，內容非空）：
1. 處方案（treatment 摘要）；2. 分鏡表縮圖（每鏡 ≥ 1 張）；3. 版本比較結果（3 版代號→風格、6 筆盲評摘要、勝者與理由）；4. 為什麼這樣剪（每段 ≥ 1 句具體理由）；5. QA 數字（qa_media 主要指標、true_peak、lint 違規數、檢查清單結果、修訂輪數）；6. 可改的地方（≥ 3 條「想要 X 就改 Y」且 Y 指向具體鏡號／參數／指令）；7. 缺鏡清單（無則寫「無」）；8. 重現指令（一行）。
缺任一段 = 不過。**必要**
- 報告數字與檔案一致：出題者抽 3 個數字（片長、lint 違規數、true_peak）與 report.json／qa 輸出比對，相同。**必要**
- 非技術使用者 30 秒內看懂「選了哪版、為什麼、怎麼改」。**加分**

## S-46 測試 —— 必要
- 新離線測試至少斷言：S-36 分類表（糊／過曝／欠曝／晃 vs 運鏡／主體被切／動能／相似）與決定性；S-37 storyboard→plan 來回；S-38 每條 lint 規則正反例；S-39 包只含 stable、壞包報錯；S-40 不選壞鏡＋剪點在拍＋不切動作中；S-41 重構圖 ≥ 98% 不出框＋最大跳動＋字幕在安全區；S-42 版本差異量與增量重算鏡數；S-43 輪數 ≤ 3；S-44 付費哨兵 = 0。
- `python -m unittest discover -s tests`（技能 venv、無 onnxruntime、無 ffmpeg 亦可）：failure 0；error 只有第一輪既有環境錯誤；新測試不得 skip（需 ffmpeg 者例外並寫明）；測試數比第三輪結束時多。**必要**
- 全套不退步（見共通規則 sha 對照）；`grep -nE "for (y|x|row|col|px) in range" scripts/fx/` 與新模組（shot_index、reframe）仍無逐像素迴圈。**必要**

## S-展示4 —— 必要（驚豔時刻）
位置（建造者定，例 `wow/fx/demo4/`）：
- **輸入**：一句想法（逐字記在 README）、素材 = repo 內 examples/ 各作品的 mp4／gif／png（只讀不改）＋程序生成素材（生成程式入庫）、一首 repo 內音樂（例 examples/neon-zen-pv/soundtrack.flac 或 wow/fx 合成曲，寫明來源與授權）。**必要**
- **全自動**：一行指令從想法到成片；README 記錄指令、牆鐘、付費哨兵計數 = 0。中途人工改 storyboard／plan = 不過（修改意見重出那次除外）。**必要**
- 產物：treatment.md、storyboard.json、人看的分鏡表、3 個版本（proxy）、盲評紀錄（6 筆）、勝出版正式 mp4（9:16 或文件化平台）、qa/report、導演報告、缺鏡清單（素材不足時）。**必要**
- 片長 15–60 s（文件寫明目標，±1 拍）；qa_media true_peak PASS；未規劃 flash／pop／freeze = 不過。**必要**
- **一句修改意見重出**：例「結尾要溫柔」或「節奏再快一點」；附修改前後對照（受影響鏡清單、重算鏡數、兩版同時間點聯絡表）。**必要**
- **與第三輪 autoplan 成對比較**：同素材同音樂跑 `fx_autoplan.py` 直接出片，與導演勝出版交給**未參與建造的獨立評審**盲評雙順序（2 筆），兩筆都判導演版勝 → 通過；一勝一平手 → 加跑一組不同評審，仍不能兩筆皆勝 = 不過。**必要**（spec：沒勝過＝導演層沒有價值）
- 不修改 examples/；不入庫第三方音檔／LUT／模型；生成素材 = 0（除非使用者同意，並寫明）。**必要**

## 看完整成品（第四輪；獨立評審原速有聲看片＋抽格，不看建造過程）
抽格：片頭 0–3 s 每 5 格；每個剪點 −3..+3 格；drop 前 2 拍到後 2 拍每格；每段字幕首／中／尾；片尾 2 s 每 5 格。三個版本與 autoplan 片各原速有聲至少看兩次；修改前後兩版並排看一次。

| 項目 | Kano | 理由 |
|---|---|---|
| **鉤子在前 3 秒**：第一個畫面就有清楚主體與動作／對比，3 秒內出現第一個節奏點；不是黑畫面、logo 慢淡入或空景 | 必要 | 短影音前 3 秒決定滑走；spec 明說「開場 3 秒鉤子選最強鏡」 |
| **大動作落在 drop**：聽到爆點那一刻看到全片最重的轉場／動作；build 有蓄力，outro 收斂；能量弧線清楚 | 必要 | 「大動作沒落在高潮」是 spec 點名的未抵達樣子 |
| **沒有選到壞鏡**：全片無糊、過曝、欠曝、手震、主體被畫框切掉（切頭、切半身）的鏡頭；定格的那格清楚 | 必要 | 導演的「眼睛」是本輪第一件事；選到壞鏡直接業餘 |
| **剪點不切在動作中間**：動作有完成感（或刻意 cut on action 且下一鏡接得上），無「話說一半」的截斷 | 必要 | 剪輯師與自動剪輯最可見的差別 |
| **轉場有變化且有動機**：轉場類型隨段落／內容變化，每個轉場說得出為什麼（運動方向延續、主體對齊、情緒轉折）；沒有連續同一招、沒有與內容無關的花招 | 必要 | spec 未抵達：「轉場與內容無關」「效果堆砌」 |
| **效果有節制**：不是每拍都閃，閃白／抖動集中在高潮；整體不刺眼、沒有連續高頻閃爍 | 必要 | 「每拍都閃」是點名的失敗樣子；也有光敏安全考量 |
| **字幕可讀且不擋臉／主體**：字級在手機上可讀、對比足夠、停留夠久（≥ 0.8 s 或文件值）、不進入平台 UI 區、不蓋主體 | 必要 | spec 點名「字幕擋臉」 |
| **橫豎轉換主體不被裁**：9:16 版主體全程在畫面內、追隨平滑不暈 | 必要 | spec 點名「橫豎版本主體被裁掉」 |
| **故事／情緒弧線**：看完能說出這支片在講什麼（呼應那一句想法），開頭、轉折、結尾有起伏，不是素材隨機拼接 | 必要 | 「像剪輯師做的」的核心 |
| **三個版本真的不同**：不看標籤也能說出三版的差別（節奏、選鏡、轉場語言），不是只換濾鏡 | 必要 | spec 未抵達：「版本之間只是換濾鏡」 |
| **盲評選出的版本確實最好**：評審自己看三版後的偏好與系統選擇一致（不一致時須能接受系統理由） | 必要 | 盲評機制的意義 |
| **導演版勝過 autoplan**：並排看，導演版明顯更像成品（選鏡、節奏、字幕、轉場動機），而非只多了效果 | 必要 | spec 自訂標竿；沒勝過＝導演層沒價值 |
| **分鏡表每一鏡的理由讀起來具體可信**，與實際畫面對得上（理由說「主體清楚、動能高」那鏡確實如此） | 必要 | spec：「每一鏡都說得出理由」；理由與畫面不符＝編造 |
| **修改意見真的生效且只改該改的**：「結尾要溫柔」後結尾明顯變柔，其他段看起來不變 | 必要 | spec：改一句話就重出 |
| **聲音**：配樂起訖乾淨、音效跟畫面同步不搶戲、無爆音 | 必要 | 第三輪延續；成片交付物 |
| **任何格無瑕疵**：無黑格、透明洞、錯位、畫布跳尺寸、殘影、裁切黑邊 | 必要 | 任一可見瑕疵即不能交付 |
| 角色動作沒被特效「發明」或取代 | 必要 | SKILL.md 既有預設 |
| 缺鏡清單的建議實際可行（指名的替代鏡真的能用） | 加分 | 讓使用者知道下一步 |
| 導演報告漂亮、30 秒看懂 | 加分 | 「say yes or no」體驗 |
| 調色在不同來源素材間統一 | 加分 | 專業質感 |
| 片中出現風格包名稱或內部術語（字幕／浮水印） | 必要（不得出現） | 盲評污染與成品專業度 |
| 預覽 GIF 大小、報告 CSS 細節 | 無感 | 不影響成片 |

## 不算通過的樣子
- 鏡頭卡把糊／被切的鏡判成好鏡，或把平滑運鏡判成手震；量測欄位由模型填寫或兩次結果不同；未看過縮圖就填 description。
- lint 有規則但正例不報、或反例誤報；為了讓 autoplan／demo 通過而放寬規則。
- storyboard 轉 plan 後時間或事件漂移；人看的分鏡表與 JSON 鏡數不同。
- 風格包含實驗效果、或包之間只差 LUT。
- 選中糊／過曝／被切的鏡；剪點不在拍上或切在動作中間；理由空泛或與畫面不符。
- 9:16 主體出框 > 2% 格、裁切框跳動、字幕進 UI 區或蓋主體。
- 版本只換濾鏡卻被當作不同版本；盲評輸入洩漏版本來源；只評單一順序；增量修改重算了未受影響的鏡。
- 修訂迴圈超過 3 輪、或把 FAIL 改成 PASS。
- 任何付費呼叫（哨兵 > 0）未經同意；入庫生成或第三方素材。
- 導演版沒有在盲評中勝過 autoplan。
- 修改 examples/ 或本答案卷。
