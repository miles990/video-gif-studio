# 流程調整（使用者 2026-11-04：「我要效果多 同時也效果好 不夠好的不要 然後是trunk based」）

## 1. 效果品質閘門：多，但每一個都要好（2026-11-05 依 thresholds.md §3 改版，取代舊的「兩位評審取低分 ≥ 4」）
舊協定在邊界附近接近擲硬幣（真 4/5 的效果只有 50–63% 通過，3.5/5 有約 40% 混進來；見 wow/fx/thresholds.md）。新協定：
- **自動檢查（必要）**：fx_gate_kit 的 alpha、拉絲、單格閃爍、黑格、決定性、720p 耗時。
- **成對比較取代 1–5 分**：每個候選效果對 (a) 同類已知好的參考效果、(b) 自己的刻意破壞版（必須贏）、(c) 換風格版（應判平手）比較。
- **評審團**：`wow-judge panel`，sonnet＋opus＋codex，兩種順序，聯絡單＋1:1 局部放大（長邊 ≤ 1280 px、JPEG 品質 ≥ 85，不設 KB 上限），每批 10–12 格（6 格時「顯著輸」只在 6/6 全輸才成立，太難刪；出題者 2026-11-05 驗算）。「平手」的操作定義：同一評審兩種順序判決不一致即算平手。
- **預先登記的判定**：對參考效果勝或平的格數 ≥ 2/3 → stable；顯著輸給參考 → 刪除；其餘維持 experimental，之後加樣本重測，不得對同一版本重抽。
- **儀器先驗**：每批開跑前放已知好（必須過）與已知壞（必須擋）；正對照不過＝儀器壞了，不判作品。
- **使用者抽查**：8 對（含隱藏的好／壞對照），問「你會直接用，還是要調？」；以信賴區間判一致性，不用固定 70%。
- 刪除不算失敗；刪除清單與理由寫進 fx.md「評估過但未收錄」。

## 2. Trunk-based
- **main 是唯一長期分支**。工作用短命分支（≤ 1 天、一個小切片），測試全綠＋該切片的審查通過就合回 main，然後刪分支。
- **功能旗標**：剛建好、還沒過品質閘門的效果註冊為 `status: "experimental"`，預設目錄看不到，
  計畫要用須寫 `--experimental`（或計畫內 `"experimental": true`）；過閘門才改成 stable。這樣半成品可以安全進 main。
- **切片順序**：
  1. 第一輪（框架＋10 個基礎效果＋fx_render／fx_reverse）在 Part A 修完並由獨立評審複驗後，先合回 main。
  2. 第二輪的框架擴充（時間重映射、補格、畫格歷史）一個切片；新效果按批（每批 4–6 個）各一個切片，每批過閘門後合回。
  3. 第三輪每個 S 項一個切片。
- **每次合回 main 前**：全套測試 0 新失敗、`doctor.py` 通過、安裝中的技能（main 就是 ~/.codex/skills/video-gif-studio 的 checkout）從乾淨狀態能跑一次 fx_render 示範。
- **對外**：使用者 2026-11-04 授權「每次合回都推」，並要求「每個小目標完成 commit+push」：每個小目標（審查、修正、切片、證據）完成就 commit 並推到 origin；合回 main 的切片另需通過測試、doctor、品質閘門。
